# PPT 工作室 · 叙事与版式手册

> **优先级**：用户指令 > 本手册经验值 > 工具默认。本手册给的是启发式与反例，**不定义任何门禁数值**；
> 门禁以 `ppt_verify` 输出为准，字段语法以 `ppt_schema` 为准（别凭记忆写字段）。
> 与工作流铁律冲突时以铁律为准；与用户风格要求冲突时以用户为准。
> **标签约定**：`经验值（可覆盖）`＝参考，可被内容或用户要求推翻；不带标签的祈使句才是本手册要你遵守的做法。
> 工具自己能报的错（字段非法/溢出/重叠）不在本手册复述——直接看 `ppt_verify`/`ppt_check` 的输出。

## 0. 一句话原则

**一页一个论点，标题就是那个论点。** 读者只看标题也能读出你的推理链，正文只是证据。
如果删掉某页不影响结论，那页就该删或合并。

## 1. 先判断你在做哪种活（决定顺序）

```
任务类型？
├─ 从头做 → 先定叙事（§2）→ 再定页序（§3）→ 再选构图（§5）→ 最后落坐标
├─ 补完（已有部分页）→ 先读已定页的 claim 序列，缺口在哪补哪；不要重排已定稿的页
├─ 只改某几页 → 只动那几页；版式沿用同册既有规则（一致性 > 你更喜欢的另一种排法）
└─ 总结/提炼（把长内容压成几页）→ 先砍事实（留支撑结论的），再排页；别把"删减"做成"缩小字号"
```

不确定就少改：**改动范围越小，用户越容易接受**。

**确认面：这些事不要替用户决定**（提问节奏仍按工作流铁律——S0 一次问全、`pause-after` 控制暂停点；快速模式按最小确认原则）：

- 主题/受众/场合在材料里**没有**，且会影响后面所有页 → 问一次（把要问的一次问完，不要连环追问）。
- 模板 vs 从零、"沿用同册风格 vs 换一套" → 给两三个候选让用户挑，不要自己拍。
- 改动范围模糊（"美化一下"到底动几页）→ 先复述你理解的边界，再动手。
- 唯一例外：用户明确说"你决定 / 随便 / 快点"——那就按默认基线做，并在交付说明里写清你替他定了什么。
- **只认已提交的确认**：你在提问后没有得到答复（用户沉默、换了话题、只丢来一个文件）都不构成确认——要么再问一次，要么按最保守的假设往下做并标注"待确认"。

## 2. 叙事 spine：七个问题定骨架

依次回答（答不出就先问用户一句，别猜）：

1. 听众是谁、他们已经知道什么？
2. 一句话结论是什么（若只能留一张纸，写什么）？
3. 支撑它的若干理由是什么（经验值（可覆盖）：2–4 个）？
4. 每个理由的证据是什么（数字/案例/引文）？
5. 听众可能怎么反驳？哪一页先挡掉？
6. 需要他们做什么（决策/批准/行动）？
7. 哪些内容**必须**放进讲稿而不是页面？

把答案写成"结论 → 理由 → 证据 → 行动"的页序，再考虑美观。顺序错了，排版救不回来。

## 3. 页序：让标题连起来像一段话

排完页后，只读标题，看是否是一段连贯的论证：

```
✗ 背景 / 现状 / 问题 / 方案 / 优势 / 规划 / 总结        （名词堆，读者不知道你要说什么）
✓ 交付周期从 32 天压到 19 天 / 卡点在两处人工交接 / 我们改了三件事 / 试点 6 组的结果 / 下一步：全线推广
```

经验值（可覆盖）：封面 + 目录（可选）+ 正文 + 结论/行动。**目录页只在页数多、结构复杂时才值得占一页**。

## 4. 标题与正文的写法

**页标题 = 结论**（其余文案的写法见 `ppt-studio-copy`：要点=证据碎片、注释=口径与条件、解释进讲稿）。

正文里的长句在语义断点显式换行（`\n`）——**断行位置是你可控的排版手段**（验证器用自己的排版估算，
按字号 × 行高与容器宽度断行，你写的 `\n` 会被尊重）。

**标题放不下时的决策顺序（只适用于标题）**：**改短标题 > 降到下一档字号档 > 拆成两页 > 压缩正文**——不要靠"标题缩到和正文一样大"硬塞
（中文方块字的视觉面积比同字号西文大，同样字数更占宽，标题尤其容易挤掉正文）。
标题能"降一档"是因为主题通常有 2–3 级标题档；**正文字号不适用这个顺序**——正文放不下时按 §6 的"删内容 > 拆页 > 调容器 > 最后才动字号"。

## 5. 按"内容量"选构图（而不是按模板库存）

**反向判据（先于选型）**：**先看清内容是什么形状，再挑构图**——内容形状对不上就换一种呈现方式，
**不要把内容塞进一个现成的构图里**（典型的坏例子：内容只有并列的概念，却画成有刻度的条形图——那是编数据）。

```
这页的核心是什么？
├─ 一个结论 + 一句支撑 → 「一句话页」：大字号 + 大量留白（最有力，也最常被忽略）
├─ 2–4 个并列项，每项一两行 → 卡片/四宫格（经验值（可覆盖）：超过 4 项先合并，或改表格）
├─ 两个对象的逐项对比 → 左右对比，逐行对齐（对齐是说服力的一部分）
├─ 有先后/因果的若干步（经验值（可覆盖）：3–6 步）→ 流程/时间线，一条主轴 + 节点
├─ 数据 → 图表页（选型与标签补齐见 `ppt-studio-data`，别只搬一个 chart 元素上去）
├─ 多维/多列文本 → 表格（不要硬塞进卡片）
├─ 多个单元其实属于**同一件事** → 「一块大面 + 分区」：用一个大面（色块/图/边框）把几个区划开，而不是每个单元发一张卡
└─ 分节过渡 → 章节页：一句话 + 页码进度即可，别放内容
```

**页面可用的表达手法**（挑着用，别每页同一种）：开场句（kicker）/ 引语 / 主数字（hero number）/ 结论条 / 口径脚注 /
分栏正文 / 单栏大段 / 全出血图 / 图文并置 / 时间轴 / 对比表。

**视觉角色分配**（先定"眼睛的第一落点"）：经验值（可覆盖）——一页 1 个主视觉（hero：面积最大、对比最强的那块）
+ 若干支撑块 + 少量最小标注（来源、单位、页码）。

**构图签名（把"该不该换排法"从感觉变成动作）**：每页动笔前写一行签名——`页任务 → 构图手法 → 轮廓/边界语言`
（例："三个卖点并列 → 三栏等分 → 直角卡片 + 细描边"）。做下一页前跟上一页对一眼：
**页任务不同、签名却相同 → 换一种手法**；**页任务相同 → 沿用同一套**（一致不是重复，成套的并列页本来就该长得一样）。

**节奏靠密度与构图，不靠改底色**：全册的底色/主色/字体是**主题的一部分**——统一才是常态（也才过得了 `theme-conformance`），
不要为了"有变化"中途换基调。真正的节奏手段是：重页与轻页交替（信息量）、章节页做呼吸（模板通常自带分区页）、
同一页内的主次对比。**深/浅切换只在一件事上成立**：模板或用户本来就设计了分区（例如封面/章节/结尾用深底），
那就沿用它的规则，而不是自己发明第二条。

**图文混排按"图片的角色"分派**（先定角色，再定版式）：

- **证据类图**（截图 / 界面 / 代码 / 图表截图）：保真优先——关键信息不能裁掉、不能压暗、不能缩小到读不出；旁边留给它足够的宽度。
- **照片类**：统一比例与高度（一页多图时不要一张 contain 一张 cover）；裁切位置自己定，主体不能切到；图注与来源写在图外。
- **装饰类/背景图**：允许出血与压暗，但**文字压图前先确认图上有一块足够干净的区域**能放下这段文字（判据是"文字要落的那块地方细节多不多"，不是一个面积比例）；
  没有就换图或改成"图在一侧、文字独占一栏"——不要整页蒙一层半透明遮罩来硬压。
- 任何情况下：`text` 压 `image` 属于需要声明的重叠，且**说不清意图就该分开**（见铁律 2 的声明制）。

## 6. 版式卫生（不需要审美天赋，只需要守规矩）

- **对齐有锚**：所有块的左边界、基线、间距从同一套栅格来（主题里的安全区与栅格就是锚）。肉眼"差不多"的对齐，在真渲染里会露馅。
- **先定焦点，再定对称与否**：一页要有一个主视觉（面积/对比最强）。**对等的两个对象 → 对分**（对称才是它们的正确形式）；
  **不对等就别硬凑成均分**（主视觉占大头、注解靠边）。模板或用户本来就是对称版式时跟随它——别为了"设计感"把对称拆成单边。
- **解读不得比证据更响**：结论条/注解的字号、颜色强度，不要盖过它要解释的数据本身。
- **留白是设计**：一页塞满说明你不会删。优先删内容，其次拆页——但**页数由用户指令决定**：页数已经定了就靠"删内容 / 换构图 / 分栏"腾地方，不要靠加页解决。
- **字号是层级工具，不是塞字的工具**：用主题 `textStyles` 的阶梯建立"标题 → 要点 → 注释"三层对比；
  内容放不下时的决策顺序是 **删内容 > 拆页 > 调容器 > 最后才动字号**（页数被用户定死时跳过"拆页"这一档），且字号下限由用户指令决定（见 §8）。
- **图片先问"看清了吗"**：插入图片要保证主体可辨（裁切别切到关键信息），尺寸与页面栅格对齐；
  图片与文字并置时，让文字区域独立成块（不要压在图上——`text` 压 `image` 属于需要声明的重叠，说不清意图就该分开）。
- **跨页一致**：页眉、页脚、页码、章节标记全册一致；颜色语义固定（同一个含义永远同一个颜色）。
- **安全区**：模板的页眉/页脚带由 `theme.safeArea`（或页面级 `safeArea`）定义，落在带上的元素会被判出界。
  有意放在带上的 logo/角标/水印，**逐个元素手工**写进 `expectedOutOfSafeArea`（不批量、id 必须存在、必须确认有意）；
  超出**页面**边界永远不可声明，只能改布局。拿不准就把元素移进安全区（先读 theme 里的 safeArea 值再定位）。

## 7. 三种"像模板生成"的典型症状与改法

| 症状 | 改法 |
|---|---|
| 每页都是"三张卡片 + 图标" | 按内容量重选构图（§5）；把其中一页做成"一句话页"做节奏变化 |
| 每页都满、都同等密度 | 交替重页/轻页；把次要证据移到讲稿与附录 |
| 标题都是名词短语 | 全部改成结论句（§4）；改不动说明这页没有论点，考虑删或合 |

## 8. 数值纪律（这一节请逐字遵守）

- 页面尺寸、页数、字号下限：**一律以用户指令为准**；用户没给就按工具的当前默认走——
  **字号下限：插件没有默认下限**（不设 `theme.minFontSize` 就不强制；导出 auto-fit 只做防荒谬保底，见 `ppt_verify`/`ppt_export` 输出）、
  页面尺寸取项目 `size`、**标准模式**页数不设配额（快速模式的页数参考见 `ppt-studio-manual` §5 交付路径）。
- **密度不是你能设的**：`density`/`hotspot` 是插件里固定的**建议级**阈值（出的是 `[~]` 警告、不入门禁），没有可配置项——
  它只提示"这页东西太多了"。"页数/字号下限/尺寸"这类**规范性的**值才以用户指令为准。
- 不要在本手册之外自造数字规则（历史上把某次任务的具体要求固化成默认，出过事故）。
- 任何"经验值"都写成"经验值（可覆盖）"，并且当用户给了风格要求时**立刻让位**。
- 不确定某个值是否合规：`ppt_verify` 的输出就是答案，不要靠猜。

## 9. 交付前自检（每条都能"数出来"或"对照工具输出"，不靠感觉）

| # | 检查 | 怎么核对 |
|---|---|---|
| 1 | 标题能连成论证链 | 把各页标题单独抄成一行读一遍：读不出结论 → 回去改标题（§4） |
| 2 | 没有"名词标题" | 数一遍：标题里带数字或判断句的比例，明显偏少就是问题 |
| 3 | 构图不重复（按任务判） | 数各页的构图签名（§5）：**页任务不同而签名相同**的对数 = 0；页任务相同则**应当**相同 |
| 4 | 密度有节奏，底色统一 | 逐页看信息量：连续多页都是"满页"→ 把其中一页拆轻；同时确认**底色/主色/字体全册一致**（中途换基调 = 颜色出板，strict 档下 `theme-conformance` 直接判 `[✗]`） |
| 5 | 图文关系已判角色 | 逐页确认：证据类图未被裁/未被压；装饰类图上的文字有干净区 |
| 6 | 页眉/页脚/页码/字体/颜色语义 | 全册一致（抽查首尾各两页对比）——**这几项工具基本不管**：`theme-conformance` 只管"颜色是否出自 theme.colors"、`aesthetic-*` 只逐页提建议，**跨页一致性没有断言**，只能自己对；别指望工具替你发现页脚页码漂了 |
| 7 | 门禁与审阅 | `ppt_verify` 的错误 `[✗]` 计数 = 0；含 table/chart/image/custGeom 的页做过真渲染抽检（**有 Office/可读图时**；否则退化为结构自检并在交付说明标注"未经视觉审阅"，不要谎报已看） |
| 8 | 出问题改在"拥有它的那一层" | 单页问题改那一页；页序/母版问题改大纲或模板；工具报错先查输入（数据/字段/媒体）——**不要在输出上打补丁**（导出后手改 pptx、绕过声明都算打补丁） |

> 第 1–6 条是自查项（自己数）；第 7 条以工具输出为准，**不过不交付**（没有 Office/读图能力时走第 7 条括号里的降级路径，并在交付说明标注"未经视觉审阅"）；第 8 条是"改在哪一层"的纪律，不是交付闸门。

## 10. 什么时候不要用本手册

- 具体字段、声明、安全区语法 → `ppt_schema`（权威且随版本更新）。
- 图表/数字怎么呈现 → `ppt-studio-data`。
- 文案措辞与"去 AI 味" → `ppt-studio-copy`。
- 用户已经有明确版式要求 → 照做；本手册只在"未指定"时给参考。
