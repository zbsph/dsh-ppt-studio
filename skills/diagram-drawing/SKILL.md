# 复杂图绘制总纲（手画 + 按需查阅子 skill）

## 铁律（每条都有代价换来的）
1. **先图后数**：任何"画好了/修好了"的结论，必须**先渲染并亲眼看图**才能下；坐标与门禁数字只作辅助。
2. **改了引擎/改了页 ⇒ 必须重出产物**（PNG/pptx）并替换到位；只改代码不重出 = 未完成。
3. **出图必过门禁**：`node scripts/verify-*.mjs` 与 `npm test`；有错先定位再改，绝不改门禁迁就图。
4. **占位必预留**：标题带 / 标签带 / 徽标栏 / 导轨栏，**先算好空间再摆元素**；后摆的东西不许压已有的。
5. **连线端点必须落在元素边上**：线的端点若不与任何元素边重合，引擎会**吸附**到附近元素 ⇒ 出现莫名长线。
6. **能力边界如实标注**：引擎不支持的东西（阴影/高光/手绘笔触）不要假装；要么不用，要么标"近似/不支持"。
7. **每条边都必须有标签**：图上任何转移/连线都要能读出"从哪到哪、什么条件"；缺标签 = **内容缺失**。门禁抓不到（实测主链 5 条标签全丢，门禁仍 0 错）——只能靠看图与旧版并排发现。
8. **有意重叠要声明**：`expectedOverlaps` 只用于**真有意**的穿入（如回路进分组容器），并写明理由；绝不用来掩盖缺陷。

## 固定流程
1. 读子 skill 拿**配方数值**（一族一份：骨架 → 流向 → 尺寸/间距 → 该族坑 → 检查清单）。
2. 生成 `elements:`（显式坐标）→ `resolveDeck` → `renderDeck`（出 HTML+layout.json）。
3. `verifyDeck` 逐页过门禁 → 有错就改（对照 pitfalls）。
4. `exportPptx` → **真渲染 PNG**（COM；不可用则 Edge 无头截预览 HTML）。
5. **自己读图**：看层级/留白/避让/连线语义（谁指向谁）→ 不满意就地改 → 回到 2。
6. 交付：PNG + pptx + 一句"这页看什么"的说明。

## 两条看图通路
- COM：`lib/msrender.js` 的 `renderPptxToPng(pptx, outDir, { pages: [...] })`（导出物必须能被 PowerPoint 打开）。
- 备用：Edge 无头截预览 HTML —— `msedge --headless=new --window-size=W,H --screenshot=out.png file:///...html`（视口要按画布比例设，否则画面会挤在角落）。
