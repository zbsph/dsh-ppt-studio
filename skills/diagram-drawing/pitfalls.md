# 踩坑索引（症状 → 根因 → 修法）

> 来源：重画 12+1 手画图 + 前 40 轮图族机制开发的实战。每条都是**真实踩过**的，附症状便于检索。

## A. 校验与结构声明

| # | 症状（门禁/报错原话） | 根因 | 修法 |
|---|---|---|---|
| A1 | `contains: non-empty array of element ids` | 给**没有内容**的形状写了 `contains: []` | 无内容就**整个省略** `contains` |
| A2 | `contains 声明不成立：父盒未真正包含子元素（pad=0）` | 子元素实际**不在**父盒矩形内（常见于"父盒加高/挪动，子元素没跟着动"） | 改父盒尺寸时**同步重排内部**（三处一起改：盒 / 标题 / 副标题） |
| A3 | `"xxx" 不是本页元素 id（防呆）` | `contains` 里引用了**不存在**的元素（或漏发该元素） | 先发元素再引用；或删掉该 id |
| A4 | `unexpected-overlap：容器 × 内部卡片` | 容器**没登记**住在里面的元素（象限容器→风险卡、泳道带→本道任务） | 容器的 `contains` 列出**全部**内部元素 id |
| A5 | `relation-invalid：容器 × 芯片内文字` | 把**芯片里的文字**当成了外层带的子元素（它属于芯片） | 文字只登记在**直接父级**的 `contains` 里 |
| A6 | `declared-stale：预期重叠声明已失效` | `expectedOverlaps` **过度声明**（声明了一对实际不相交的元素） | 只声明**真正相交**的对；删掉多余的 |

## B. 连线与几何

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| B1 | 页面上出现**莫名长横线**，或线端点"吸附"到别的元素上 | 线的端点**不在任何元素边上** ⇒ 引擎自动吸附 | 端点**精确落在元素边**（x = 卡左边/右边，y = 卡心） |
| B2 | `unexpected-overlap：卡 × 线`（交叠十几像素） | 线的起点画在卡**内部**（如 `A.x + 6`） | 端点改到**卡边**（`A.x`）并声明 `side: left` 等 |
| B3 | `unexpected-overlap：泳道带 × 跨道连线` | 跨道连线**必然**穿带（泳道图的设计本质） | 按纪律**显式声明** `expectedOverlaps` 并写明"属设计意图"，**不得改门禁** |
| B4 | 回边竖管**压住卡下标签** | 车道基准没让开标签带 | 车道整体下移（≥ 标签带高 + 8px）；标签放在车道**上方** |
| B5 | `style-connector-off-target：还有 4.0px` | 连接符尖端离目标轮廓太远 | 尖端**贴住**目标边（±2.5px 内） |
| B6 | 环形图连线从卡心出发、压住卡片 | 同 B2 | 用**卡边 + 沿环方向**裁剪端点（`off ≈ 半卡宽`） |

## C. 文字与间距

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| C1 | `text-overflow：估算宽 65px / 容器 44px` | 节点多于列宽、或左对齐槽位没重算 | 槽宽从卡片重算；**放不下按度量自动缩字号**（下限 9pt） |
| C2 | `content-collision：标题 × 副标题`（交叠 2px） | 两行文字框挨太紧 | 拉开 ≥4px；或加高父盒并两行一起重排 |
| C3 | `style-badge-too-tight`（徽标压字） | 徽标竖栏居中，压到第二行文字 | **有副标题时徽标与标题同行** |
| C4 | `style-contrast-low：1.22:1`（白字压浅蓝渐变） | 浅色/渐变底上硬用白字 | 文字色按**对比度自动选**；渐变要按 **stops 两端取最差**判 |
| C5 | 标签被线穿过 | 标签落在车道上 | 标签移到车道**上方**一行 |

## D. 工程与流程（我踩过、代价最大的）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| D1 | `ReferenceError: require is not defined in ES module scope` | 脚本存成 `.mjs` 却用 `require` | CJS 用 `.cjs`；ESM 用 `import` |
| D2 | 脚本语法错、输出乱码/`ParserError`，反复改不对 | 把带 `\n`、引号的复杂 JS **塞进 PowerShell here-string** ⇒ 转义层层叠加 | **用文件工具直接写脚本文件**（字节可控）或**直接写 YAML** |
| D3 | `Slides.Item : Integer out of range. 2 is not in…` | 渲染请求的页数 > pptx 实际页数 | 按 `ctx.pages.length` **动态**传页数 |
| D4 | 改了引擎"看起来修好了"，用户打开的还是旧文件 | **只改代码没重出产物** | 铁律：改了引擎/页面 ⇒ **重出 pptx/PNG 并替换到位** |
| D5 | 只看坐标就宣布"修好了"，实际图上仍有问题 | 数值 ≠ 观感 | 铁律：**先读图再下结论**；图与门禁互补，二者都给 |
| D6 | 补丁"语法正确、构建通过"，目标却没变化 | 锚点落在**别的族/别的分支**（8 个族共用相似代码） | **插桩定位**（在可疑函数里放唯一标记，渲染后看 notes 是否出现）；或先算**函数区间**只改区间内 |
| D7 | 门禁/合规抓不到"内容缺失"（如标签全丢） | 门禁只查几何与可读性，不查语义完整性 | 与**旧版并排读图**对照内容；把"每条边都要有标签"写进清单 |
| D8 | 复杂度量爆炸：改了盒高，子元素掉出盒外 | 尺寸改动**没有联动** | 改尺寸时**同时**检查：父盒、内部元素、连线端点 |

## E. 渲染与交付通路（2026-09 实测补充）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| E1 | 交付的 PNG 与源码/门禁不一致（改了页面但图没变），且 sha 与旧版一字不差 | **有进程打开着目标 pptx（尤其 PowerPoint）**⇒ COM `Presentations.Open` 拿到的是**内存里的旧副本**，静默渲染旧内容 | 渲染前确认没有进程占用该 pptx；**重出前先清空输出目录**，避免旧 PNG 残留被当成新图复制 |
| E2 | `exportPptx` 抛 `open … .pptx`（EBUSY/EPERM）、管线中断 | 同上，文件被 PowerPoint 锁住 | 请用户关闭后重出；或导出到新文件名 |
| E3 | 复制出的 PNG 是别的/更早的页面 | 复制步骤依赖渲染器输出名（`01.png…`），若渲染失败/被锁则**复制的是上次残留** | 渲染后校验输出文件的时间戳/sha 再复制；失败就中断，别静默复制 |
| E4 | 读图复核时看到的是旧图（同路径读两次结果完全相同） | 看图通路**按路径缓存**了归一化副本 | 复核大改后的页面时，**复制到新文件名再读**（或改路径） |

## B7. 斜边 prst 的端点：轮廓 ≠ bbox

| 症状 | 根因 | 修法 |
|---|---|---|
| 平行四边形/chevron 等斜边形状旁边，箭头看着"没接上"（留 ~15px 缝） | `parallelogram` 的路径是 `(0,h)→(x1,0)→(w,0)→(w−x1,h)`，`x1 = adj/100000 × min(w,h)`（默认 adj=25000）⇒ **腰高处可见边比 bbox 内缩 x1/2** | 端点按**轮廓**算：左/右侧各内缩 `x1/2`（118 高时约 15px） |
| 按轮廓修完反而报 `unexpected-overlap 形状×线` | **门禁按 bbox 判形状** ⇒ 端点进入 bbox 必报重叠 | 这属 bbox×斜边轮廓的**固有偏差**，按纪律 `expectedOverlaps` **显式声明并写明理由**（不是掩盖缺陷）；或改从**上下边**接入（水平边无内缩，最干净） |
