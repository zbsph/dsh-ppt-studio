# PPT 工作室 · 图与数据手册

> **优先级**：用户指令 > 本手册经验值 > 工具默认。本手册只给启发式与反例，**不定义任何门禁数值**；
> 门禁以 `ppt_verify` 的实际输出为准，语法细节以 `ppt_schema` 为准（不要凭记忆写字段）。
> 本手册与工作流铁律冲突时，以铁律为准。
> **标签约定**：`经验值（可覆盖）`＝参考，可被内容或用户要求推翻；不带标签的祈使句才是要遵守的做法。
> 工具自己能报的错（字段非法/数值全零/溢出）不在本手册复述。

## 0. 先分清"这张图是证据还是装饰"

**先判断用途，再决定要不要标签**——这一步比标签本身重要：

| 用途 | 要不要标签 | 怎么做 |
|---|---|---|
| **图表承载数据结论**（读者要读出值/趋势/对比） | 要 | 分类名、数值、单位、一句结论句缺一不可（§2 给两种补法） |
| **图表作装饰 / 示意 / 版式衬底**（不承载结论） | **不必** | 让它纯几何即可；**别让它假装承载数据**（要么标注"示意"，要么干脆用形状） |
| 介于两者之间 | 按"读者是否需要读出值"判 | 拿不准就至少给单位与一句"读图结论"——结论句写在**图外**（§2 路径 A），不是往图里塞标签 |

**成品层（交付物）**：导出的 .pptx 里 `chart` 元素**只画几何**——柱/折线/饼形，
**没有**分类名、数值、单位、坐标轴、图例（实测：导出包里没有任何 chart 部件，slide XML 里只有你自己写的 text 元素）。

**预览层（`ppt_render` 的 HTML）也不是"什么都画"**：bar/line 会画分类名（**超过 8 字截断**）+ 5 条网格线与**数值刻度**（那个 y 轴是按最大值归一化的，不代表真实量纲）；
**pie 不画分类名，却照样画那套 y 轴刻度**（对饼图毫无意义）；**每个数据点的具体值只在悬停提示里**。
所以"预览里看着能懂"对饼图根本不成立，对 bar/line 也仅是分类名与相对刻度可读。

→ **预览是定版参考，交付物是 pptx**：只按预览确认"图表能看懂"，交付出去可能就是一张没有标注的图形。

→ **承载数据的图表** = 图表元素（几何）+ 你自己补的文本（分类名/数值/单位/图例/结论）。
→ **装饰性图表** 可以不带标签，但交付说明里加一句"该图仅作示意"（本手册的补充建议，不在铁律 7 的必含项里），并且不要用它去支撑页面结论。

## 1. 选型：先问"读者要读到什么"

**前置红线（先于选型）**：**手上没有可比数据时，不要用图表或任何带刻度的数值视觉**。
概念列举画成条形、没有基数的百分比画成柱、随手写个"约 60%"——这些是**门禁测不出来的失真**（`ppt_verify` 管几何，不管真假）。
没有数就老老实实写文字或用并列卡片；需要数就先去要数据。

**数据拥有图形（不许反向）**：图上的每一个量化标记（柱长/折线点/扇区角度/色阶）都必须来自**权威值 + 一个显式的比例换算**：
不许目测摆位置、不许为了画面好看改数据、**非零基线的坐标轴必须在图上写明**（否则读者会按面积误读倍数）。

```
读者要读到…
├─ 一个数的大小/趋势 → 图表（bar 比大小 / line 看趋势）
├─ 精确到个位的具体值 → 表格（table）或大字数字 + 一行注释
├─ 两三个数 → 不要图表：大字数字块（shape 衬底 + text）最有力
├─ 占比 → pie 只在类别很少时才读得出（经验值（可覆盖）：约 4~5 类以内）；类别多 → 横向条或表格
├─ 多维/多列文本型数据 → 表格；不要硬塞进图表
└─ 只是"意思一下"的装饰 → 不要用图表假装有数据（`chartIssue` 只拦"空数据/全零"，编造的非零值**没有任何工具会拦**——要么标注"示意"，要么干脆用形状）
```

经验值（可覆盖）：一张图只表达一个结论；同一页不要放两张互相抢注意力的图；
饼图类别越少越好（多了人眼比不出角度）；柱形从 0 起，折线可以不从 0 起但要在注释里说明。

**图表配色与主题**：`chart.colors` 不写 → 用**内置调色板**（它**不在 `theme.colors` 里**，`ppt_verify` 不会报，但成品会带主题外颜色）；
要与主题一致就显式写 `colors: ["$primary", "$accent"]`（`$ref` 在**预览与成品两层**都会被解析成 hex）。
**显式**写了不在 `theme.colors` 里的颜色 → 会出一条 `[·] aesthetic-theme` 建议（**建议级，不是门禁**）——逐条斟酌，别当成错误去清。

## 2. 补齐标签的路径（含门禁语义）

`role` 推断是固定规则：**text / table / chart 都算 content**，shape / image 算 background，line 单独一类。
所以"文本压在图表上"= **content×content = 永远错误、不可声明**：

- ✗ `[✗] content-collision｜元素 "label" 与 "chart" 重叠（交叠 N×Mpx）—— 内容互压（文字/表格/图表相互遮挡），不可声明豁免，请调整布局`（真实报告的措辞，N×M 是实测交叠尺寸）

**先按图的角色选路径（这一步决定你能用哪条）**：

- **图承载结论**（读者要从它读出值）→ **只有 A 一条路**：标签移出图框。这种情况不存在"合法的压上去"。
- **图是衬底 / 纯装饰**（不承载结论、页面结论不依赖它）→ 可以用 B 或 C，把"这张图就是底"写成显式声明。

| 做法 | 怎么写 | 代价 |
|---|---|---|
| **A. 标签放图表框外**（默认，永远可用） | 图表 bounds 缩小，分类名/数值/图例排在图框上/下/左/右的空白区 | 需要预留空间（图表别占满整页） |
| **B. 图当衬底**（仅衬底类图） | 给 chart 加 `role: background`，再把这组重叠写进该页 `expectedOverlaps` | 声明的是"这张图是承载文字的底"——语义变了，且**文字压在图形上仍然难读**，声明不会替你解决可读性 |
| **C. 图纯装饰**（仅纯装饰图） | 给 chart 加 `role: decoration`，**完全退出重叠报告**（不用写声明） | `decoration` 的语义是"此元素不承载信息"；只豁免**重叠**，不豁免超页面/超安全区/文本溢出 |

**`role` 不是消错开关**：把承载数据的图标成 `background`/`decoration` 去让 `content-collision` 消失，
是"在输出上打补丁"（craft §9 第 8 条明令禁止）——报错在告诉你文字和图互相盖住了，不是在告诉你改个字段。
判据只有一句：**这张图到底承不承载结论**。承载 → A；不承载 → 才轮到 B/C，而且这是设计决定，不是消错手段。
`role: decoration` 还可能掩盖别的读者问题（图看不懂、图与结论无关），所以用它之前先确认"这张图本来就不需要被看懂"。

## 3. 口径三件套：值、单位、基准

任何数字页，读者必须能回答三个问题：**这个数是多少 / 单位是什么 / 跟什么比**。

- 单位与量级写在标题或就近的标注里（"销售额（万元）"），不要只放在页脚。
- 对比要有基准：同比/环比/目标值/同业——没有基准的百分比等于没信息。
- 精度按决策需要给：金额到万就不必到元；比率一位小数通常足够。
- 图表页建议在页面 `source:` 写依据（制度/报告/口径），交付前用 `ppt_crosscheck` 生成"数据来源核查表"：
  有 `source:` 的页标 grounded，没有的标 unmapped。**注意它按"页"判、不看这页有没有数据**，而且 `ppt_crosscheck` 是**建议级**（不构成门禁）——
  所以要求是"**重要数字页都有 `source:`**"，不是"全册 unmapped = 0"（封面/章节/纯文字页本来就没有数据来源可标）。

## 4. 跨页数字必须同口径

同一个指标在多页出现时，值、单位、时间范围、口径必须一致（`ppt_crosscheck` 会把跨页重复数字列成组让你核对）。
常见事故：第 3 页写"增速 12%"，第 9 页同一指标写"13%"——读者只会记住"这人不严谨"。
改口径就改全部出现处，或在页面上显式说明两个口径的差别。

## 5. 表格（最容易被低估的可读路径）

`table` 的字段是**元素级**的（不要写到 `chart:` 里）：

```yaml
- elementId: tbl
  elementType: table
  bounds: [60, 420, 840, 120]
  cols: ["指标", "本期", "同比"]
  rows: [["任务闭环率", "94%", "+33pt"], ["按时交付率", "91%", "+19pt"]]
  header: true
```

经验值（可覆盖）：列在 5 列、行在 7 行左右开始难读；表格不是"信息仓库"，一页表格只服务一个结论；
超过可视面积就拆页，不要靠缩字号硬塞。**2026-09-18 起表格有了自己的溢出断言**：`[✗] table-overflow`
（按列宽换行估算内容高 vs 表格高，与正文同一保守度量）——处置是**扩大表格高度 / 加宽列 / 精简单元格文案**。
但 **`ppt_verify` 仍不检查图表的溢出**（溢出断言只覆盖 `text` 与 `table`；`density` 只是元素计数的 `[~]` 警告）：
图表放不放得下仍需靠 `ppt_render`/真渲染目检。
注意：table 只有 `cols / rows / header` 三个字段（**没有逐列对齐字段**，以 `ppt_schema` 为准）——
要靠列宽、表头写单位、把关键值拆成大字数字块来建立层级，而不是指望"右对齐"。

## 6. 结论句：图表必须有人替它说话

每个数据页写一句"读图结论"，放在图旁（不是图里），句式：
**主语 + 变化 + 幅度 + 含义**，例如"任务闭环率从 61% 抬到 94%——流程改造的收益主要落在执行环节"。

- 结论句里出现数字时，必须与图上/表上的数字**逐字一致**。
- 不写"显著提升/大幅改善"这种没有量级的形容（那等于没结论）。
- 图上有异常值就解释它，不能假装没看见。

**放进页面的图，不要自带"页面零件"**：用来配图/示意的图片（含导入素材、生成的示意图）不该自带页眉、页脚、页码、标题栏、角标、署名或装饰边框——
那些是 deck（主题/母版）的职责。自带 chrome 的图一旦入 .pptx 就是**不可拆的重复元素**，而且门禁不会报错，只能靠你在选图时看一眼。

## 7. 常见坑（逐条对应工具输出）

| 现象 | 原因 / 处理 |
|---|---|
| 导出报告提示图表数据解析为全零或无效 | `chartIssue` 命中：检查 `chart.data.cols/rows` 映射；单列 pairs 兼容但**建议宽表** `cols: [分类, 值]` + `rows: [[类, 值], …]` |
| 多系列只画出一条 | 宽表只给 `cols` 时按第一组取值；多系列要显式写 `series:` 映射——`series: [{name: "本期", x: "分类列名", y: "数值列名"}]`（`ppt_schema` 只有一句提示、没有样例，形状见 `svgCharts.js` 的 `chartData`） |
| 预览能看懂、成品看不懂 | 若这张图是**承载结论**的（§0 判据），就是标签没补；若它只是装饰/示意，属于正常，交付说明里注明即可 |
| 图表页报 `content-collision` | 先判图的角色（§2）：**承载结论 → 只能 A**（标签移出图框）；**纯衬底/纯装饰 → B/C**（改 `role` 是设计决定，不是消错开关）。这是"改布局"还是"改声明"的分叉，不是措辞问题 |
| 数据页报**未声明重叠**（非 content-collision） | 属于声明制范畴：确认是有意叠层 → 补 `expectedOverlaps`；说不清意图 → 改布局 |
| 数据页出现 `density`（`[~]` 警告）或 `aesthetic-text`（`[·]` 建议） | 都不是门禁；但一页塞两组数据 + 三条结论确实读不动，拆页更好 |

> 分级术语对齐门禁输出：`[✗]` 错误必须清零、`[~]` 警告需处置/声明、`[·]` 建议斟酌采纳（`[⚠]` 只出现在 M2 实测交叉段，不是主清单标记）。

## 8. 交付前自检（每条都能"数出来"或"对照工具输出"）

| # | 检查 | 怎么核对 |
|---|---|---|
| 1 | 图表用途已逐页判定 | 每张图能说清是"证据"还是"装饰"（§0）；证据类 → 分类名/数值/单位/结论句**四件齐**，装饰类 → 交付说明加一句"仅作示意"且页面结论不依赖它；改过 `role` 的图要能答"这张图本来就不需要被看懂吗" |
| 2 | 数字有来源、无编造 | 页面上每个数字都能指回材料或用户；**重要数字页都有 `source:`**（`ppt_crosscheck` 是建议级、按页判——封面/章节页 unmapped 是正常的，别当成错误去清） |
| 3 | 跨页同口径 | `ppt_crosscheck` 的跨页数字组逐组核过：同一指标的值/单位/时间范围一致 |
| 4 | 图形没有骗人 | 逐图检查：柱形从 0 起；折线非 0 基线已注明；没有按面积比较却没标基线的图 |
| 5 | 配图无自带 chrome | 逐图看：没有图内页眉/页脚/页码/角标/边框 |
| 6 | 门禁与真渲染 | `ppt_verify` 的 `[✗]` 计数 = 0；含 chart 的页用 `ppt_visual` 真渲染复核过（**没有 Office/读图能力时**退化为结构自检 + 导出 parity，并在交付说明标注"未经视觉审阅"，不要谎报已看） |
| 7 | 交付说明 | 写明：哪些图仅作示意、数据口径与假设、未标注来源的项 |

> 第 1–5 条自己数；第 6 条以工具输出为准，**不过不交付**。

## 9. 什么时候不要用本手册

- 纯文字/纯版式页（去 `ppt-studio-craft`）。
- 文案本身的措辞与"去 AI 味"（去 `ppt-studio-copy`）。
- 字段语法、声明写法、安全区配置：不要查手册，直接 `ppt_schema` / `ppt_check`（权威、随版本更新）。
- 给既有稿**补一页或补一组标签**时：先读该册已定页的口径与标注习惯（单位写法、`source:` 写法、图表配色），
  沿用同册规则，不要引入你自己更喜欢的另一套。
