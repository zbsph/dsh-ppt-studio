# PPT 工作室 · 图与数据手册

> **优先级**：用户指令 > 本手册经验值 > 工具默认。本手册只给启发式与反例，**不定义任何门禁数值**；
> 门禁以 `ppt_verify` 的实际输出为准，语法细节以 `ppt_schema` 为准（不要凭记忆写字段）。
> 本手册与工作流铁律冲突时，以铁律为准。

## 0. 先记住一条成品事实（很多人栽在这）

**导出的 .pptx 里，`chart` 元素只画几何**——柱/折线/饼形，**没有**分类名、数值、单位、坐标轴、图例。
这条是实测结论（导出 slide XML 里只有你自己写的 text 元素，图表数据不会变成文字）。

而 **HTML 预览里的图表是带分类名的**（`ppt_render` 那条通道会画，名字超过 8 字截断）——
**预览是定版参考，交付物是 pptx**。只按预览确认"图表能看懂"，交付出去就是一张没有标签的图形。

→ 交付级图表 = 图表元素（几何）+ **你自己补的文本**（分类名/数值/单位/图例/结论）。
→ 只做内部草稿或明确"图表仅作形状示意"时，可以不补，但要在交付说明里写明。

## 1. 选型：先问"读者要读到什么"

```
读者要读到…
├─ 一个数的大小/趋势 → 图表（bar 比大小 / line 看趋势）
├─ 精确到个位的具体值 → 表格（table）或大字数字 + 一行注释
├─ 两三个数 → 不要图表：大字数字块（shape 衬底 + text）最有力
├─ 占比 → pie 只在类别很少时才读得出（经验值（可覆盖）：约 4~5 类以内）；类别多 → 横向条或表格
├─ 多维/多列文本型数据 → 表格；不要硬塞进图表
└─ 只是"意思一下"的装饰 → 不要用图表假装有数据（会被 chartIssue 或读者识破）
```

经验值（可覆盖）：一张图只表达一个结论；同一页不要放两张互相抢注意力的图；
饼图类别越少越好（多了人眼比不出角度）；柱形从 0 起，折线可以不从 0 起但要在注释里说明。

## 2. 补齐标签的两种做法（含门禁语义）

`role` 推断是固定规则：**text / table / chart 都算 content**，shape / image 算 background，line 单独一类。
所以"文本压在图表上"= **content×content = 永远错误、不可声明**：

- ✗ `[✗] content-collision｜元素 "label" 与 "chart" 重叠 —— 内容互压，不可声明豁免`（实测原文）

两条合法路径：

| 做法 | 怎么写 | 代价 |
|---|---|---|
| **A. 标签放图表框外**（推荐） | 图表 bounds 缩小，分类名/数值/图例排在图框上/下/左/右的空白区 | 需要预留空间（图表别占满整页） |
| **B. 图表降为背景层** | 给 chart 加 `role: background`，再把这组重叠写进该页 `expectedOverlaps` | 图表被声明为背景层（语义上"承载文字的底"）；仍是有效交付，但要确认这是你的设计意图 |

A 是默认姿势；只有当"标注必须压在图内"（例如在柱子上标注数值）时才用 B，并且**声明即意图**——
说不清为什么压上去，就该改布局而不是声明。

## 3. 口径三件套：值、单位、基准

任何数字页，读者必须能回答三个问题：**这个数是多少 / 单位是什么 / 跟什么比**。

- 单位与量级写在标题或就近的标注里（"销售额（万元）"），不要只放在页脚。
- 对比要有基准：同比/环比/目标值/同业——没有基准的百分比等于没信息。
- 精度按决策需要给：金额到万就不必到元；比率一位小数通常足够。
- 图表页建议在页面 `source:` 写依据（制度/报告/口径），交付前用 `ppt_crosscheck` 生成"数据来源核查表"：
  标注过的页是 grounded，未标注页会提示 unmapped——**别把 unmapped 留在交付里**。

## 4. 跨页数字必须同口径

同一个指标在多页出现时，值、单位、时间范围、口径必须一致（`ppt_crosscheck` 会把跨页重复数字列成组让你核对）。
常见事故：第 3 页写"增速 12%"，第 9 页同一指标写"13%"——读者只会记住"这人不严谨"。
改口径就改全部出现处，或在页面上显式说明两个口径的差别。

## 5. 表格（最容易被低估的可读路径）

`table` 的字段是**元素级**的（不要写到 `chart:` 里）：

```yaml
- elementId: tbl
  elementType: table
  bounds: [60, 420, 840, 120]
  cols: ["指标", "本期", "同比"]
  rows: [["任务闭环率", "94%", "+33pt"], ["按时交付率", "91%", "+19pt"]]
  header: true
```

经验值（可覆盖）：列在 5 列、行在 7 行左右开始难读；表格不是"信息仓库"，一页表格只服务一个结论；
超过可视面积就拆页，不要靠缩字号硬塞（放不放得下以 `ppt_verify` 的溢出/密度输出为准）。
注意：table 只有 `cols / rows / header` 三个字段（**没有逐列对齐字段**，以 `ppt_schema` 为准）——
要靠列宽、表头写单位、把关键值拆成大字数字块来建立层级，而不是指望"右对齐"。

## 6. 结论句：图表必须有人替它说话

每个数据页写一句"读图结论"，放在图旁（不是图里），句式：
**主语 + 变化 + 幅度 + 含义**，例如"任务闭环率从 61% 抬到 94%——流程改造的收益主要落在执行环节"。

- 结论句里出现数字时，必须与图上/表上的数字**逐字一致**。
- 不写"显著提升/大幅改善"这种没有量级的形容（那等于没结论）。
- 图上有异常值就解释它，不能假装没看见。

## 7. 常见坑（逐条对应工具输出）

| 现象 | 原因 / 处理 |
|---|---|
| 导出报告提示图表数据解析为全零或无效 | `chartIssue` 命中：检查 `chart.data.cols/rows` 映射；单列 pairs 兼容但**建议宽表** `cols: [分类, 值]` + `rows: [[类, 值], …]` |
| 多系列只画出一条 | 宽表只给 `cols` 时按第一组取值；多系列要显式写 `series:` 映射（`ppt_schema` 有样例） |
| 预览能看懂、成品看不懂 | 就是第 0 节那条：标签没补 |
| 图表页报 `content-collision` | 文本压到了图表框里 → 按 §2 走路径 A（标签移出图框）或路径 B（chart 加 `role: background` + 声明）。**这是"改布局或改声明"的分叉，不是措辞问题** |
| 数据页报**未声明重叠**（非 content-collision） | 属于声明制范畴：确认是有意叠层 → 补 `expectedOverlaps`；说不清意图 → 改布局 |
| 数据页出现 `density` / `aesthetic-text` | 这类是 `[·]` 建议（不是门禁），但一页塞两组数据 + 三条结论确实读不动，拆页更好 |

> 分级术语对齐门禁输出：`[✗]` 错误必须清零、`[⚠]` 警告需处置/声明、`[·]` 建议斟酌采纳。

## 8. 交付前自检（照着过一遍）

1. 每个图表页：分类名、数值、单位、结论句**四件齐**，且数字与正文一致（对着 `pages/*.yaml` 里的文字元素核一遍）。
2. `ppt_verify` 0 错误（`[⚠]` 逐条处置或声明，`[·]` 斟酌）。
3. `ppt_crosscheck`：跨页数字组逐组看过；重要数据页 `source:` 已标注。
4. **含 chart 的页做视觉复核**：有 Office（或可读图）时用 `ppt_visual` 真渲染该页再看一眼——
   **真渲染图才是读者会看到的样子**；没有 Office / 没有读图能力时，退化为结构自检（parity + 图表数值清单），
   并在交付说明里如实标注"该页未经视觉审阅"（不要谎报已看）。
5. 交付说明里写明：图表是否只作形状示意、数据口径与假设、未标注来源的项。

## 9. 什么时候不要用本手册

- 纯文字/纯版式页（去 `ppt-studio-craft`）。
- 文案本身的措辞与"去 AI 味"（去 `ppt-studio-copy`）。
- 字段语法、声明写法、安全区配置：不要查手册，直接 `ppt_schema` / `ppt_check`（权威、随版本更新）。
- 给既有稿**补一页或补一组标签**时：先读该册已定页的口径与标注习惯（单位写法、`source:` 写法、图表配色），
  沿用同册规则，不要引入你自己更喜欢的另一套。
