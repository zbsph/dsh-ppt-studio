## 2. 目标（长期不变）

1. **一个可验证的 PPT 生产工作流**：产出质量由"数字门禁 + 视觉审阅"双轨保证，而不是靠运气。
2. **四类任务同一个中间层（PPTD）**：deck.yaml + pages/*.yaml + media/ 是唯一事实源，引擎可插拔。
3. **迭代友好**：每次改动有回归（smoke 断言集）、有文档（本目录）、有版本（semver + git）。
4. **元目标**：从"熟练工才能用得顺"进化到"人人可用"（用户测试反馈 3.3 的一句话总结）。

**演进主线**（为什么每一步这么做）：
- 先保主链路可跑 → 再用真实文件（WPS）逼出兼容性问题 → 用真实任务（产能 PPT 19 页）逼出**工具摩擦**（声明成本、度量偏差、安全区、自述缺失）→ 每个摩擦做"插件级修复"，**不改用户工作流习惯**（声明制保留，只是给一键生成）。
- 原则：**严格性（错误门禁）不可降**；**使用成本必须降**。两者冲突时优先保严格性，用自动化降低成本。

## 4. 关键设计决策（已定，勿轻易推翻；推翻 = 必须更新本文件）

1. **中间层 = 自定义 PPTD v1**（独立实现，不依赖 Kimi 逆向生态）。
2. **重叠合法性 = 设计意图声明制**（expectedOverlaps 对照），不是元素类型制；**内容互压（content-collision）永远不可豁免**。
3. **双轨审阅**：数字门禁（render→verify，ERROR 清零）+ 视觉审阅（shot + read_image）；估算档已被证明会漏报 → 视觉审阅不可省。
4. **引擎 auto = pptd（主引擎，图表矢量拼绘）**；python-pptx 仅显式指定或 pptd 硬失败时使用。
5. **样式只用 theme token**；中文最小字号 12pt 为工作流铁律（导出缩字下限 = theme.minFontSize，默认 12）。
6. **Aesthetic `[·]` 建议永远不是门禁**（用户要求审美改进不得引入冲突错误）。
7. 产物 = 中间层项目 + .pptx；`1px = 1pt`；尺寸默认 960×540。
8. 预设 = standard 全量 + 插件行；`C:\Users\11867\.dsh\.agent-presets\ppt\`。
