# 07 · 复杂图能力：立项说明与风险登记（讨论稿）

> 状态：**立项讨论稿，未开工**。决策人：用户；执行：Lead。
> 目标一句话：**大幅提高「用 PowerPoint 原生形状拼出复杂结构图」的能力上限；同时不得降低任何既有能力。**
> 本文件是用户与 Lead 于 2026-09-27 讨论的产物，后续每阶段的验收与风险核对都以本文件为准。

---

## 0. 背景：瓶颈在哪

用户的真实工作（例：某比赛稿第 9–16 页）需要**由几十到上百个原生形状拼出的复杂图**：单页实测 **59 / 77 / 102 / 98 / 91 / 112 / 148** 个形状节点，构成是
`rect`/`roundRect` 盒 + `straightConnector1`/`bentConnector3`（肘形）+ 箭头（含两端）+ `chevron`/`notchedRightArrow`/`parallelogram` 流程符号 + `custGeom`/`FREEFORM` 手绘 + 容器/嵌套 + 旋转 + 阴影。

核对现状（代码依据）：形状词汇、旋转、箭头、custGeom、导入的组合拍平**都已具备**；真正缺的是
① **没有「结构→几何」的编译层**（模型必须手算上百个坐标，这是能力上限的真实瓶颈）；
② 连线不能"挂到形状边"、没有正交路由；
③ 没有容器的首类概念（组合）；
④ 图专属校验缺失（箭头未落边、线穿盒、元素重复/共位、文本压文本）。

---

## 1. 目标与非目标

**目标**
1. 有结构的图（流程、层叠架构、层级树、时间轴、对比、矩阵/象限、闭环反馈、步骤环…）**由结构描述生成几何**，而不是手算坐标。
2. 产物必须是**原生形状**（可编辑、可手术、可被 `ppt_patch`/`ppt_splice` 处理），不是图片。
3. **机械校验 + 独立视觉审阅**双把关：机械能判的写死在代码里；机械判不了的（箭头方向、依赖一致性、层级语义、遮挡、强调一致性）交给**带固定清单的独立审阅**。

**非目标**
- **不改变风格主导权**：风格一律来自 ① 用户指令 ② `$theme` ③ 用户给的参考稿；引擎不引入自有审美。
- **不为特定场景设定"好坏标准"或"领域惯例"**：PPT 适用面太广，执着于某一场景的"好"会损害泛用性（见 §9.1）。
- 不用位图/图片模拟结构图（图片素材仍走既有 image 通道）。
- 本立项内**不新增运行时依赖**。

## 2. 北极星场景与验收

**场景**：用户给一份已有复杂图的 pptx，要求"**再加一页同风格的复杂图**"。
链路：`ppt_import`（参考层 + 样式档案）→ 图 IR → 布局引擎 → `ppt_splice` 插回原稿（**其余页逐字节不变**）。

**验收三关（全过才算达标）**
1. **机器关**：门禁 0 错误 + `parity.ok`（含图的新判据）+ 官方 `check_office.py` 通过 + 图专属校验 0 错误。
2. **视觉关**：真渲染（PowerPoint COM）逐页出图 + **独立子代理按固定清单审阅**（结构化结论、写进交付说明）。
3. **对照关**：与"今天手写坐标"的同一页对照，**重叠 / 箭头脱靶 / 对齐错误**的下降必须显著。

> 说明：用户抽看渲染图是**开发期验收行为**，不写进插件工作流。插件内的"视觉审阅"仍指模型用真渲染 + 读图自查成品（既有 P1 铁律）。

## 3. 设计决定（D1–D9）

| # | 决定 | 理由 / 影响面 |
|---|---|---|
| **D1** | 图能力做成**「IR 编译器」**：声明式图 IR → 布局引擎算几何 → 落成**现有元素** | 新能力不碰导出/预览主链；既有 measure/verify/preview/shot/patch/export 全部复用；生成后仍可手改 |
| **D2** | 风格**只**来自用户指令 / `$theme` / 参考稿样式档案；引擎无自有审美。**裁决优先级：用户口头要求 > 参考稿 > 其他（主题/引擎默认）**（细则见 §9.3） | 用户优先是铁律；"加一页同类图"要看起来本来就是那份稿子的一部分 |
| **D3** | 声明词汇升级：`contains` / `attach` / `badge` / `group` 类型化结构声明 + **脚本推导** + **几何反验证** | 复用既有 `role` 三值、`decoration` 全豁免、声明的传递闭包、同源 id 前缀豁免、超页面不可声明；把"逐对手写"换成"结构推导" |
| **D4** | **组合两步都做**：① 逻辑分组（校验/审阅/命名/声明/剪枝）；② **`grpSp` 真导出**（前提：用户可在 PowerPoint 里手动"取消组合"，拆开后仍是可编辑原生元素） | 第一步不动导出主链、风险极低；第二步才去啃组坐标空间（`off/ext` vs `chOff/chExt`）、嵌套、组内旋转；用户裁定要真组合（见 §9.4） |
| **D5** | 审阅：机械检查 + **独立子代理按固定清单视觉审阅**（作者不参与自审；审阅者只看渲染图 + 需求原文） | 自审偏弱（确认意图而非发现缺陷）；清单化 + 结构化输出才可核验、可入交付说明 |
| **D6** | **确定性**：同一 IR 两次 ⇒ 几何逐字节一致 | 我们大量断言依赖逐字节可复现；禁止不可复现随机，必要时固定种子并记录 |
| **D7** | **度量**：优先"布局 → 实测 → 重算"回流（HTML 在真浏览器里量），可选接 Pillow 真字体度量；配安全余量 | 现在用估算（CJK 1em/latin 0.55em），"留白怪异"是已知问题；实测回流最省 |
| **D8** | **回归守门**：无图任务 prompt 增幅 ≤5%；无图页产物**逐字节不变**；门禁语义变化必须在报告里显式说明 | 这是用户那条硬约束（不影响既有能力）的可测形式 |
| **D9** | 知识分层：**schema**（IR 语法）/ **工作流 3–4 行**（必做纪律）/ **新 skill**（图族与边界规则、审阅清单、失败模式） | 常驻成本最小化、深度知识按需加载 |
| **D10** | **范围态度：清单内项目都做**，不追求"最小可行"；图族清单按**全量经典族冻结** | 这是复杂大工程；部分族可停 80%，但必须标 `maturity` 且**优雅降级**（见 §9.2） |
| **D11** | **审阅锚点分工**：可机械反查 → 既有门禁；可证据核验的判断 → 抽样复核；纯审美 → 用户 | 审阅者只负责把"纯审美之外"筛掉，不代替用户下判断（见 §9.8） |

## 4. 「组合」的多层语义（用户真实工作流的工程化）

用户的真实做法（第 15 页为例）：
1. 先把小件（背景图案 + 图片 + 文本框）合成**第一层组合**，确认**组内**无意外冲突；
2. 把该组合放上更大的背景、与其它文本框构成**第二层组合**，此时**把第一层当成一个整体**，只确认它与第二层其它元素无意外冲突；
3. 再把第二层当作整体去画整页流程图；
4. 审阅同样逐层做：**每层都能独立做「计算审阅（坐标/IR）+ 视觉审阅（这个组合本身画得怎么样）」**。

**工程含义（五条）**
| # | 含义 | 说明 |
|---|---|---|
| G1 | 组是**剪枝单元**（broad phase），但**剪枝 ≠ 豁免** | 组间包围盒相交的仍要落到元素级真实判断；只有包围盒确定不相交才排除候选。否则就是假阴性 |
| G2 | 组级**裁剪渲染**：孤立视图 + 上下文视图 | 审阅时两视图都要看：孤立图看清"这块本身画得如何"，上下文图看清"放到页面里是否压迫/失焦" |
| G3 | **几何指纹 + 审阅失效** | 组的几何/内容/样式一变，之前的"已审阅"必须作废（否则"上次审过"变成假绿）；指纹相同才可跳过重审 ⇒ 支撑**增量重审** |
| G4 | 组 = **可复用块**（局部坐标 + 参数），默认 **copy 语义** | 跨页复用需显式操作，不做隐式联动（可预测优先）；这是"块库"的天然入口，也带来块库治理问题（见风险 R23） |
| G5 | 嵌套深度建议 **≤3 层**，超限提示拆页 | 层数过多人/模型都会对"这一层是什么"失焦；组必须**语义化命名**（id 可读） |
| G6 | 组合**复用既有的同源 id 前缀豁免** | 组内元素共享前缀 ⇒ 天然按结构豁免，不新造机制 |

## 5. 阶段与交付（A–D）

| 阶段 | 内容 | 目的 / 验收要点 |
|---|---|---|
| **A. 地基（不含新能力）** | ① 结构声明 `contains/attach/badge/group` + 推导脚本 + **几何反验证** + 报告聚合；② 元素重复/共位、文本压文本（永不声明）、线穿盒、箭头未落边检查；③ prst 白名单补齐（如 `notchedRightArrow`）、>2 点折线、head+tail 箭头、虚线样式；④ 150 元素**性能与报告体量**基线；⑤ `role` 覆盖可见性（覆盖必须带 reason、进报告与交付说明） | 钉死**确定性、性能、判据严格性、图进 parity**；单独就能提升现有上限（箭头落边、双向、正交） |
| **B. 图编译核心** | IR + 布局框架 + 样式档案（theme/参考）+ 物化为现有元素 + 预览↔成品**同源** + 结构关系自动产出 + 组级裁剪渲染 | 能力上限的核心引擎；**确定性断言**与**无图页字节不变**在此固化 |
| **C. 图族库（分批，全部覆盖）** | 每批 2–3 族；每族 = 布局策略 + 契约夹具 + 真渲染验收 + 组级/页面级审阅 | 图族**清单需冻结**；每族标 `maturity: stable｜beta`；未完成族必须**优雅降级**（退回简单布局或手写路径），不得产出半成品图 |
| **D. 北极星 + 块复用** | 参考稿样式档案 → 同构换内容；组合作为可复用块跨页/跨稿复用 | 命中用户真实需求；结构抽取结果必须**可视化回放**给人确认 |

**图族清单（待用户圈定，建议冻结）**：流程图、泳道图、组织/层级树、分层架构（输入→处理→输出）、时间轴/里程碑、闭环反馈、左右对比、矩阵/象限、步骤环、漏斗/金字塔、时序图、状态机。

## 6. 风险登记册

> 状态：**已缓解**（已有对策且成本可控）｜**待观察**（对策明确，需实测）｜**用户已表态**（用户已给出处理方式）。
> "早期信号"是我们要主动去测的，不是等它发生。

### A. 能力本质类

| ID | 风险 | 早期信号 | 对策 | 阶段 | 状态 |
|---|---|---|---|---|---|
| R1 | **几何正确 ≠ 逻辑正确**：箭头方向、依赖关系、层级语义机械检查验不出来，可能"更快地画出更多错的图" | 出现"几何全绿但一眼不对" | 独立子代理按清单审阅（方向/依赖/层级/遮挡/强调一致性）；IR **回读成一句自然语言结构描述**供核对；业务真值仍需用户或源材料 | B/C | 待观察 |
| R2 | **视觉自洽 ≠ 业务正确**：模型不知道"A 是否真的先于 B" | 审阅说"没问题"但内容错了 | 明确边界：机械+审阅只保证"图自身自洽"；业务正确性由用户/源材料负责，交付说明写明 | 全程 | 用户已表态（接受） |
| R3 | **观感退化**（几何全绿但不好看） | 用户说"不如我手工那张" | 独立子代理按清单审阅 + 与上一版权威渲染**逐页对照**；固定义夹具 | B/C | 用户已表态（用子代理审阅） |
| R4 | **信息密度失控**：能力变强诱导"堆满一页" | 单页元素数持续上升、可读性下降 | 审阅清单加"投影可读性/必要元素"项；skill 给密度建议；必要时提示拆页 | C | 待观察 |
| R5 | **自然语言→IR 的语义映射错误**（漏环节/合并概念）比坐标错更致命 | 结构描述与需求对不上 | IR 可读 → 渲染前先核对结构描述；审阅清单首项即"与需求是否一致" | B | 待观察 |

## 9. 追加讨论结论（2026-09-27 第二轮）

> 本节是第二轮讨论的结论，**对 §1 / §3 / §6 / §7 / §8 作更新，冲突处以本节为准**。

### 9.1 泛用性优先（更新 §1）

用户裁定：**不为特定场景/行业设定"好坏标准"或"领域惯例"**——PPT 适用面太广，执着于某个场景的"好"反而会损害泛用性。因此：
- 引擎只保证"**结构正确 + 节奏专业 + 不劣化既有能力**"，**不内置行业图式偏好**；
- 密度/拆页这类"惯例"**不作为立项强约束**，交由用户指令与参考稿决定；
- 验收只用"结构正确性 + 与手写基线对照 + 用户抽看"，**不引入场景特定的评分标准**。

### 9.2 范围态度（新增 D10）

**清单内项目都做，不追求"最小可行"。** 这是一个复杂大工程：图族全量、`grpSp` 真导出、块复用、Pillow 度量、审阅机制**均在范围内**。
允许某族停在 80%，但必须：① 标 `maturity: stable｜beta`；② **优雅降级**（退回简单布局或手写路径，不得产出半成品图）。

### 9.3 风格与冲突裁决（更新 D2）

**裁决优先级：用户口头要求 > 参考稿 > 其他（主题/引擎默认）。**
细则（例如参考稿内部风格自相矛盾时取"最新页"还是"多数派"）**留待后续版本讨论**，本次只把它写成规则骨架。

### 9.4 组合：真 `grpSp` 导出纳入范围（更新 D4）

两步都做：① 逻辑分组（校验/审阅/命名/声明/剪枝）；② **`grpSp` 真导出**。
**硬前提**：用户能在 PowerPoint 里**手动"取消组合"**，拆开后仍是可编辑的原生元素（不产生不可逆锁定）。
新增要求：
1. 组坐标空间（`off/ext` vs `chOff/chExt`）、嵌套组、组内旋转/翻转必须过**真渲染回归**；
2. **取消组合后的语义**：元素 id 与结构声明仍有效；原先"组原子化"带来的剪枝不复存在，需退回元素级检查（报告要说明）；
3. 与 G4 一致：块复用默认 **copy 语义**，不做隐式联动。

### 9.5 跨组"故意相交"的声明（补 §4）

```yaml
groups:
  - {id: A, members: [e1, e2]}
  - {id: B, members: [e3, e4]}
expectedIntersections:
  - {from: A.e1, to: B.e4, reason: "A 的徽章压在 B 的卡片上（设计意图）"}
```

语义（注意：这是"剪枝 ≠ 豁免"那句话的另一半）：
1. **设计期校验**：两端存在且**当前确实相交**；若实际不相交 ⇒ 只给 ℹ（"声明已失效，建议移除"），**不报错**（意图是"允许相交"而非"必须相交"）；
2. **运行期**：先用组间包围盒**剪枝**候选对，再逐对判定——在声明集合里 ⇒ 放行；否则 ⇒ 报错；`content × content` **永不放行**；
3. **失效绑定**：任一组几何指纹变化 ⇒ 跨界声明需重验（与 G3 一致）；
4. **断言**：既有的"声明传递闭包"**不得沿跨组声明传播**——声明 (A.e1, B.e4) 不能连带放行 (A.e2, B.e4)；
5. 连线端点的相交优先用 `attach`（语义化、可几何反验证）；裸 pair 只留给"说不清接口、就是故意压叠"的场景（徽章/衬底）。

### 9.6 组合的六种操作 + "醒着做"（补 §4）

操作：**拆散 / 部分拆出 / 重组 / 合并 / 整组移动·缩放 / 替换成员**。
"助手必须清醒"落成**机械形式**：
1. 组合操作是**带必填 `action` + `reason`** 的工具调用；
2. 操作后**报告事实**：成员去向、哪些声明仍有效、**哪个不变量失效**、已重跑哪些检查；
3. **拆开 → 改动 → 重组**后给"变了什么"的 diff，**不允许静默重排**。

### 9.7 "缝合页"的症状与防线（补 §4 与 R9）

| 症状 | 表现 |
|---|---|
| 间距节奏不齐 | IR 块内 16px、手写部分 13/17px ⇒ 一眼"松紧不一" |
| 差几像素对不齐 | IR 块左边 x=60、手写元素 x=63 ⇒ 说不出哪里怪但就是不对 |
| 圆角/描边两套语言 | IR 统一圆角 6px/描边 1pt，手写 4px/0.75pt ⇒ 像两种零件 |
| 字号阶梯塌陷 | IR 走主题 20/16/12，手写 18/15 ⇒ 层级看着"平" |
| 命名与结构对不上 | IR 块有语义 id，手写是 `t1/t2` ⇒ 审阅/手术时说不清归属 |
| 交互行为不一致 | IR 组可整块拖动，手写部分要一个个挪 |

防线：① 两条粒度**读同一套 token**（间距基数/字号阶梯/圆角/线宽来自 `$theme`/参考档案）；② 混用时检查手写元素**是否落在 IR 网格上**（提示级，不报错——手写是合法逃生口）；③ 视觉审阅清单加一项"**这页是否像一套**"。

### 9.8 审阅锚点分工（新增 D11）

| 清单项类型 | 锚是谁 | 做法 |
|---|---|---|
| **可机械反查**（箭头落边/意外重叠/元素重复/文本压文本） | 既有门禁 | 审阅者说法与几何不符即可**直接证伪** |
| **可证据核验的判断**（方向与正文相反/与旁边文字不是一件事/投影看不清） | 抽样复核（开发期 Lead，发布后用户） | 审阅者必须**引用证据**（页/元素/现象），抽样成本极低 |
| **纯审美**（整体专业感/视觉动线） | **用户** | 关键节点抽看；发布后由用户反馈 |

配套：独立子代理审阅（**作者不参与自审**）、只看"渲染图 + 需求原文 + 结构声明与理由"、按固定清单逐项作答、结论进交付说明；**审阅者的"没问题"会被抽样复核，并记录其命中率**——命中率差就换审阅者或把该项升级为机械判据。
