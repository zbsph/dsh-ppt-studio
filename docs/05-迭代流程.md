# 05 · 迭代流程（每次改动的检查单 + Git/发布约定）

## 一次迭代的标准循环（推荐顺序）

1. **读文档**：`docs/01-需求与目标.md`（冲突清单 C* 是否受影响）+ `docs/04-路线图.md`（本迭代目标）。
2. **定目标**：1 个主目标 + ≤3 个小修；写进 `docs/03-更新日志.md` 待办行。
3. **改代码**：只改 `src/`（lib 由 build 生成，勿手改）。
4. **同步文档**（铁律，缺一不可）：
   - `docs/02-技术报告.md`：模块/机制/契约变了就改；波及面速查表对应行打勾。
   - `docs/01-需求与目标.md`：需求/决策/冲突清单有变化就改（推翻决策必须写"为什么"）。
   - `README.md`：使用者可见的行为变化（工具面/参数/规则/子集表）。
   - `src/scaffold.js` `SCHEMA_REF`：DSL 语法有变化就改（与 README/技术报告三处一致）。
   - 工作流提示词（`src/router.js`）：铁律/入门段有变化就改（模型看到的 = 文档）。
5. **构建**：`node scripts/build.mjs`（src → lib）。
6. **回归**：
   - `node scripts/smoke.mjs`（必须全绿；新增特性 → 增量断言，坏例优先"先写失败测试"）。
   - `node scripts/regression-real.mjs`（真实资产：19 页 deck + WPS fixture）。
7. **生效**：首选**重启 DSH host**（保底且干净——注入器注册表自动恢复全部插件；无任何挂起状态）。
   - 备选：`dev_reload_package dsh-ppt-studio`——**已知缺陷（2026-09-04 排查）**：build 后立即手动重载与 watcher 自动重载并发时，`ctx.loader.import` 可能产生"僵尸 in-flight job"，同 URL 后续 import 永久排队 → 工具调用卡死（注入器已加超时/锁/cache-bust 三重防护，但**僵尸 job 通道为宿主侧限制，不能保证 100% 免疫**）。**实践经验：build 后若 30 秒内 watcher 自动重载未完成，直接重启，不要反复手动重载**。
   - **新增事实（2026-09-05 确认）**：本插件经 agent preset 行**会话级装配**（include 机制），不在注入器 loader 域——`dev_reload_package` 无法命中（重载空转），`dev_plugin_status` 也不显示。**改码 → 重启 host 是唯一可靠生效路径**（注入器 0.3.4 起该工具会给出明确诊断）。
8. **记录**：`docs/03-更新日志.md` → `## [版本号] 日期` 目的/改动/验证/影响；改 `package.json` version（semver）；git commit（message 含版本号）。

## Git 约定

- 仓库根 `D:\SharkCode\dsh-ppt-studio`（无远程；可后接 GitHub Release）。
- `.gitignore`：`node_modules/`、`lib/`（build 生成）、`examples/*/preview/`、`examples/*/imported/`、`examples/*/out-*.pptx`、`examples/*/media-test.png`、构建产物目录（import-realtest* 等）。
- 提交粒度：一个功能/修复一个 commit；message：`v0.x.y: <一句话目的>（反馈 Dx）`。
- **基线 commit**（v0.3.0 + 文档体系）已于 2026-09-04 建立——从此任何改动可 diff/回滚。

## 版本与发布

- semver：`major` 破坏中间层/接口兼容；`minor` 新特性；`patch` 修复/文档。
- 发布清单：smoke 全绿 → 真实回归全过 → README/SCHEMA_REF/更新日志同步 → **重启 DSH host 确认 active**（dev_reload_package 仅作补充，见步骤 7 已知缺陷）→ （未来）`dev_release_plugin` + npm pack。
- 运行时装配路径（勿动）：profile `node_modules/@dsh-external/dsh-ppt-studio`（junction → 本目录，**供 preset 行解析包名——必须保留**）；预设 `C:\Users\11867\.dsh\.agent-presets\ppt\`（standard 全量 + 插件行，**唯一装配源**）。

## 装配注意（2026-09-04 教训入库，v0.14.2）
- **本插件有两个装配源**：注入器 registry 恢复（host 启动）+ agent preset 插件行（agent 挂载）——同包可能装配两次（时序竞态曾导致 duplicate 路由崩溃）。
- **凡 host 资源注册（webServer 路由等）必须幂等**：globalThis refcount（模块级变量在 junction/真实路径双加载下不可靠）——见 preview-server.js ROUTE_REG 范式（首个注册者真注册、最后卸载者真卸载）。
- 新资源注册一律 `ctx.effect`（清理即净）。

## 装配定论（2026-09-05，v0.14.6 起单源）
- **装配源 = agent preset 插件行（唯一）**：`C:\Users\11867\.dsh\.agent-presets\ppt\agent.cordis.yml` 的 `ppt-studio` 行（include 会话级装载）。
- **注入器 registry 的 ppt-studio 记录已清除**（历史残留，来源：09-03 dev_inject_plugin 实验）——保证永不出现双源。**junction 保留**（`profiles/web/node_modules/@dsh-external/dsh-ppt-studio` → 本目录）：preset 行靠它解析包名。
- **开发工具的现实约束**（注入器 0.3.4 起已诊断化）：`dev_reload_package` / `dev_plugin_status` 只覆盖注入器 loader 域；preset 行装配不在其中 → 改码 = 重启 host；`dev_build_plugin` 不再把 DSH_CHECKOUT 当构建前置（copy-only 插件无需 checkout；需要 tsc 的插件由其 build.sh 报明确错误）。
- **yaml@2 节点 API 教训**：`parse()`（纯值）/ `Document.toJS()`（Document 级纯值，推荐）/ `doc.get()`+`node.toJS()`（AST 层，裸 toJS 抛 "A document argument is required"）——parseDocument 场景读值一律 `doc.toJS()`。

## 新反馈的处理模板

1. 归类：插件层（工具/DSL/断言）/ 提示词层（工作流/铁律）/ 环境层（DSH/系统，记录但不改插件）。
2. 标 ★（影响面）：≥1 个★ → 进下一轮主目标；无★ → 进 backlog（docs/04 维护段）。
3. 写复现：先造"坏例"进 smoke（红）→ 修（绿）——防回归。
4. 更新 docs/01 §5 冲突清单（新张力就开新 C 行）。

## 反馈文件纪律（2026-09-06 起）

- **测试反馈 .md 是易失文件，随时可能被删除/移动——不得作为后续工作的依据**。每条反馈的实质（现象/根因/修复/验证）必须**当轮落入 git**：docs/03（更新日志）/ docs/04（记录）/ docs/06（评审）；反馈文件名只作溯源引用，不依赖其存在。
- 复盘与后续迭代一律从 git 记录出发；反馈文件还在时只做交叉核对。

## 发布-同步纪律（机器 == GitHub 字节级）

- **每次更新 = 一条命令**：`node scripts/release-sync.mjs`（package.json scripts 已挂 `sync`）。原子完成：build → pack → sha256 比对/上传（--clobber，幂等）→ **同一 tgz 部署本机安装根**（`D:\plugins\package`）→ 终验 sha256 三向一致 → 写 `.sync-state.json`。
- **本机跑的就是 GitHub 给的**：本机安装包由发布用同一个 tgz 解压而来，sha256 与远程资产一致；升级只重复此命令（无需手动下载）。
- 版本号：未获用户指示不改（当前 1.0.0）；同 tag 资产原地更新，`updated_at` 变化即新包。

## 宿主升级纪律（DSH 换版本时必做，2026-09-12 起）

- **先确认版本再动手**：`dsh --version` + `npm view @deepseek-ai/dsh dist-tags`（`latest` 与 `next` 可能不同；本机基线写进 README §0.1 与 package.json 的 peer 范围）。
- **契约逐项核对，不靠记忆**：对本机活进程用 Inspect 取权威签名——`Service.listService`（`tools` / `commands` / `systemPrompt` / `webServer` / `skills` / `agent*`）与 `Event.listEvents`（`session/event` / `system-prompt/assemble`）。**服务名与事件载荷都可能变**（本轮实例：DSH 只有 `agents` 服务，`agent` 服务并不存在）。
- **会话身份只走官方通道**：工具内 = `execute(args, exec)` 的 `exec.agent`；waterfall/命令内 = `context.agent` / `invocation.agent`。禁止 `ctx.get('agent')`。
- **升级后必须"真进程验证"，不能只跑单测**：临时覆盖层（`dsh --profile headless --patch <overlay.yml> "<任务>"`）+ 落盘探针，实测三件事——① 插件 host 装配成功且工具可调；② 内嵌 skill 在技能注册表里可见（`ppt_state.manualSkill.visible`）；③ `system-prompt/assemble` 里确实出现 `ppt-workflow` 段（探针计数，别问模型"你看到没有"——模型自述不可信）。
- 覆盖层与探针文件属临时物，验证完立即删除；headless profile 的 junction 用 `cmd /c rmdir` 删（`Remove-Item -Recurse` 有跟随重解析点删目标内容的风险）。
- **绝不对可能含 junction 的目录做 `Remove-Item -Recurse`（2026-09-14 事故，已修复）**：
  本机 `~/.dsh/profiles/web/node_modules/yaml` 与 `D:\plugins\package\node_modules\yaml` 都是 junction，
  而 PowerShell 5.1 的 `Remove-Item -Recurse` **会跟随重解析点**。事故链条：临时对照包被 `install.mjs` 链上
  `node_modules/yaml`（指向 dsh 安装内的 yaml）→ 随后 `Remove-Item -Recurse` 该临时目录 →
  **把 `@deepseek-ai/dsh/node_modules/yaml` 的内容清空**（目录还在、包没了）→ dsh 整棵插件树加载失败
  （`dsh-settings-file` / `dsh-credentials-local` 找不到 `yaml`）。
  修复：从本机同版本副本（`~/.dsh/profiles/web/node_modules/yaml`，yaml@2.9.1，满足 `^2.9.0` 与 `^2.4.2`）**普通复制**回
  `@deepseek-ai/dsh/node_modules/yaml`，用 `dsh --version` + `dsh --profile headless --help` 验证插件树恢复。
  规矩：① 删任何目录前先 `cmd /c rmdir <里面的 junction 子目录>`；② 临时包用 `cmd /c rmdir /s /q` 或 Node `fs.rmSync`（不跟随重解析点）；
  ③ **造对照包一律用普通复制（`Copy-Item`）并自带 `node_modules/yaml`，不要用 `install.mjs`**（它会建 junction）；
  ④ 指向宿主的链接用完立刻删。
- **预设行也要比对（2026-09-12 血案）**：`agent-presets/ppt/agent.cordis.yml` 是**随包 standard 预设的全量副本 + 插件行**，宿主的预设行配置会随版本漂移（实例：0.1.5-rc.2 把 dsh-persona 的 `text` 改成 `prefix`+`suffix`，副本没跟 → 一切换预设就弹 `$.prefix missing required value`，单测与工具契约核对都发现不了）。每轮升级后跑 `node scripts/check-preset.mjs`（`npm run test:preset`），有漂移即修。
- **跨层验证（2026-09-14 连线方向血案）**：同一份内容有三层产物——HTML 预览（render-html.js）、OOXML 成品（export-pptx.js）、真渲染图（Office/Edge）。**任何一层单独通过都不算过**：实测出现过"预览全对、PowerPoint 里斜线镜像/× 少一笔"（`straightConnector1` 丢 `flipH`/`flipV`）。规矩：凡新增/修改元素类型的导出编码，必须 ① 加**从产物反推的自证断言**（如 `connectorEndsFromXml` 端点比对进 `report.parity`）② 至少一页 `ppt_visual` 真渲染人眼复核。

## 内置技能的增改纪律（2026-09-14 起）

技能是**内容**，不是代码——它会直接影响模型行为，且用户看不到 diff。因此按以下规矩增改：

0. **禁令准入（借 ppt-master 的 prompt-style 判据，2026-09-14 引入）**：手册里每一条"禁止/必须/配额"都必须能说出**让它变硬的机制**
   （`ppt_verify` 的哪条断言、导出器行为、格式限制、门禁顺序、读入成本）；说不出机制的 → **降级为"经验值（可覆盖）"或删掉**。
   这条是防止手册越写越僵、越写越像说教的唯一闸门。配套两条：
   - **单一所有者 + 指针**：同一规则只在一处写全，别处只写"见 §N / 见某工具"；复述即产生第二所有者，两边必然漂移。
   - **标签强度分级**：用 `**硬规则**` / `**默认（可覆盖）**` / `**参考·非约束**` 把"必须"和"建议"在字面上分开——
     模型把风格建议当硬规则执行，正是我们出过事故的样子。
   - 反向红线：**绝不把别家 skill 里的具体数值当默认基线抄进来**（它们的"Default — X"读起来像推荐默认值，抄进来同时违反第 2 条并让插件变差）。
0a. **外部经验值的两道闸（2026-09-14 用户抓到的失误，务必照做）**：从外部 skill / 文章吸收任何经验值前必须过两关——
   ① **机制闸**：这条能说出机制吗？说不出 → 不进手册（顶多写成"参考"）。
   ② **原则闸**：它与我方既有门禁 / 原则冲突吗？冲突 → **一律不进**，哪怕它在别处是主流做法。
   失误实例：从 ppt-master / 归藏的调研报告里抄了"同一明暗基调连续 3 页以上就该换"，它**说不出机制**，
   而且与 `theme-conformance`（颜色必须出自 theme）和"模板基调统一"直接冲突——会把模型推向"中途换底色"这种更差的结果。
   已删除，并把正确口径写成"**节奏靠密度与构图，不靠改底色**；深/浅切换只跟随模板或用户既有的分区设计"；
   同时加了一条 smoke 防线（劝人改全册底色/主色 = 违规），校准：5 条植入违规全抓、6 条合法表述零误报。
0b. **不吸收第二套门禁**：外部 skill 的校验脚本/自检命令/配额表一律不搬——我们只有 `ppt_verify` 一套门禁语义；外部能做而我们不能做的（联网、生图、HTML 运行时）不写进手册。
1. **只增不改**：工作流提示词由 `scripts/fixtures/workflow-baseline.json` 做**逐行超集**断言（`npm test` 里两条"★老用户不受影响"）。新增指引＝加一行；**任何对旧行的改写或删除都必须先经用户确认**，确认后跑 `node scripts/dump-workflow-baseline.mjs` 重建基线（不确认就别重建——重建会让护栏失效）。
2. **不许写死数值**：技能正文不得出现"默认 12pt""必须 ≤8 页""每页 ≤40 字"这类**规范性数值**。smoke 有 5 条校准过的正则做机器防线（8 条植入违规全抓、8 条合法表述零误报）。经验值一律写成"经验值（可覆盖）"，并把优先级写成"用户指令 > 手册 > 工具默认"。
2b. **自检条目要可核对**：自检章节的每条都应能"数出来或对照某个工具输出"（存在性/计数/一致性），不写"是否美观""是否清晰"这类无法核对的话
   （借归藏 checklist 的"现象→做法→机械自检"形状；P0 项必须先清零）。
   > **这道守卫的诚实边界**：正则只能抓"规范性措辞 + 数值"这一形状，**抓不到**"裸阈值当建议写"（如"列 ≤5、行 ≤7 才好读"）、也抓不到语义偏移（把"逐元素手工声明"写成"站在带上就声明"）、不可执行的指令（要求 table 右对齐）与三本之间的重复。所以 `docs/06 §7.4` 的**独立评审**是必需的第二步：新写或大改技能后，交一个独立 agent 逐条对照源码评审，把缺陷清单落进 docs/03。
3. **每本自包含且短**：描述 ≤500 字符且**只写触发**（描述会常驻系统提示，正文按需加载）；正文几千字符量级；不放脚本、不依赖外部文件。新增一本＝新建 `skills/<kebab-name>/SKILL.md`，`install.mjs` 与 `lib/skill.js` 自动纳入（无需改代码）。
4. **不与用户自装技能抢位置**：一律 `ppt-studio-*` 前缀；通用能力（去 AI 味、润色）写"优先用用户已装的同类技能，本手册兜底"，不复制别人的内容。
5. **改动要有前后对照**：技能效果属"软收益"，必须用 A/B 评测（同一 brief、同模型、同装配，门禁分数 + 信号扫描）落到 docs/03/04；不做"感觉更好了"的结论。

## 禁止事项（保护性底线）

- 不删标准预设任何行（预设 = standard 全量 + 插件行）。
- 不把任何 ERROR 降级为 warning（严格性只升不降；降 = 必须用户确认 + 更新 01 文档）。
- 不静默切换引擎（auto 语义 = pptd；切换必须显式或用户确认）。
- 不做无视用户指令的自动缩字（下限 = 用户指令 theme.minFontSize；未设仅 60% 原字号防荒谬保底，绝不升字）。
- 不引入新的运行时 npm 依赖（yaml 是唯一例外；新增须论证）。
- **不拿"能跑通"当"没问题"**：凡"机制应当生效"的断言（提示词注入、技能交付、会话状态、路由判据），必须有**可观测证据**（探针计数 / 注册表查询 / 状态文件），否则记为"未验证"。
