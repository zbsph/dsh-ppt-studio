# 图族"授人以渔"机制设计 · 状态机族试点（阶段 E）

> 用户口径（2026-09-30，必须遵守）：
> **不提供内置风格画像。** 风格来源只有两种 —— ① **用户要求优先**（指令/参考图/任何形式）；② 用户没要求时，**助手按当前场景与内容自行设计**。机制只负责"不管什么风格，图都不出错"。

## 1. 三条宪法（机制之所以能"不管什么风格"的命门）

1. **风格不得改拓扑与端口**：节点行列位置、连线进出边、走哪条车道 —— 只由"画法"（族）决定。
2. **风格可改三类东西**：① 间距/密度等**常量**；② **绘制方式**（填充/渐变/描边/圆角/字体/连接符形状/箭头样式）；③ **附加装饰层**（背景卡、导轨、水印）——只能画在内容**下层**，且必须通过装饰检查。
3. **风格要新做法 ⇒ 必须新增"结构特型"(trait)，并且同时提交它的合规检查与负面对照**；未知 trait/trait 值 ⇒ **报错**，不得静默忽略。

## 2. 风格的两块拆分（"无限风格"与"有限支持"的边界）

| 块 | 例子 | 引擎态度 |
|---|---|---|
| **paint（无限）** | 颜色、渐变停靠、线宽、字体族/字重、圆角半径、阴影 | **直通**（不可能破坏几何 ⇒ 任意风格都可用） |
| **traits（有限闭集）** | 卡片形态、徽标、副标题、连接符形状、导轨、密度、边框、起止标记 | 引擎必须**懂**：有实现 + 有检查 + 有用例；**加一条就必须带一条检查** |

## 3. 状态机族的 traits 闭集（Y1 冻结）

```yaml
style:
  card:      { shape: rect|roundRect|pill, fill: <paint>, border: <paint>, elevation: none|soft|strong }
  badge:     none | number            # 状态编号圆徽（左上）
  subtitle:  true | false             # 卡内第二行（进入动作/说明）
  label:     inside | below           # 状态名在卡内还是卡下
  edge:      { glyph: arrow|chevron|open, width: number, backStyle: solid|dashed }
  edgeLabel: masked | plain           # 标签是否带底板遮线
  markers:   none | startEnd          # 初始/终止态标记（小实心圆/圆环）
  density:   compact | normal | loose # 只影响间距常量
  frame:     { title: true|false, rails: none|rows|return }   # 顶部标题带 / 行导轨 / 回边导轨
```

**允许影响布局的"安全通道"（逐条列明，越界即视为违宪）**：

| trait | 允许影响 | 不允许影响 |
|---|---|---|
| `card.shape` | 文本安全内边距、锚点真实轮廓 | 行列位置、端口侧 |
| `badge` | 卡内左侧预留栏、最小卡宽 | 端口侧、车道 |
| `subtitle` / `label` | 卡片最小高度、文本槽位、行距常量 | 连线拓扑 |
| `edge.glyph/width` | 箭头端直段最少长度、端口微偏移 | 路由形状（仍正交、仍避障） |
| `density` | 行距/列距/车道步长常量 | 路由候选集合与优先级 |
| `frame.title/rails` | **预留带**（标题带、导轨带成为路由障碍） | 端口侧、拓扑 |

## 4. 绘制意图（intent）：族输出"画什么"，渲染两端消费

```
layoutState(content, style) -> {
  frame:  { titleBox?, noteBox?, bands: [...] },          // 预留带（同时是路由障碍）
  nodes:  [{ id, box, shape, outlineAttach, textSlots:[{kind:title|sub, box, paint}],
             badgeSlot? }],
  edges:  [{ id, from, to, isBack,
             ports: { from:{side,pt}, to:{side,pt} },
             route: [[x,y]...],
             glyph: arrow|chevron|open, paint,
             label: { text, box, masked } }],
  decor:  [{ kind: rail|band|card, geometry, paint }],     // 只允许在下层
  invariants: { lane, candidate, fallback?, reservedBands: [...] },  // 供门禁与"过程自证"核对
  notes:  [ 'honored trait: ...', 'lane = top@y=73.1', 'fallback: 无' ]
}
```
**纪律**：预览（`render-html`）与导出（`export-pptx`）**消费同一份 intent** ⇒ 预览=成品（parity 可查）。

## 5. "能防的防、防不住的查"（本族历史踩坑 → 机制化处理）

| 历史坑（本会话实证） | 新机制里的位置 |
|---|---|
| 回边形成 L 形屏障、从下方绕必穿 | **候选集合 + 打分**（车道/外侧走廊/上方车道）；无解即回退并在 `notes` 说明（"防"） |
| 折返尖刺（相邻点共线折返 ⇒ 戳出一根线） | `normalizePage` 兜底规整（"防"）+ 门禁 `line-spike`（"查"） |
| 标题带被车道/标签占用（此前靠"省略标题"绕过） | `frame.title` ⇒ **预留带成为路由障碍**（"防"，取代绕过） |
| 端点没贴边 / 悬空 | `relations.outlineAnchor` 真实轮廓 + 门禁 `line-end-off-edge` |
| 线穿盒 | 候选打分（节点命中数）+ 门禁 `line-on-box-edge`/重叠判据 |
| 交叉 | 门禁 `line-crossing` + 候选打分（"查"+"防"） |
| 文字溢出卡片 | 门禁溢出检查 + trait 化后仍守（"查"） |

## 6. 过程自证（Y4 要求：不只做成，还要证明是**机制**在起作用）

1. 测试内容 = **纯语义 YAML**（≈15 行：nodes/edges + style 块），**不写任何坐标**；
2. 产出证据：族 `notes`（实际生效的 traits、所选车道、是否回退）、门禁结论、**语义行数 vs 生成元素数**、**迭代轮数**（目标 1）；
3. 三风格对照：同一份语义 + 三个 `style` 块 ⇒ 若节点/边拓扑**逐项一致**（可机械比对），即证明"风格只换皮、不破画法"。
