## 2. 每个族的交付定义（DoD）

1. **布局策略**：写在该族的 `layout()` 里，只做几何；取色/字号/线宽/间距**全部来自样式令牌**（族没有审美）。
2. **契约夹具**：进 `scripts/verify-diagram-ir.mjs` 的族用例表（确定性 / schema 合法 / 落在画布内 / attach 端点落边）。
3. **真渲染验收**：导出 + PowerPoint COM 出图 + **读图确认**（人眼过一遍"像不像这个族"）。
4. **组级/页面级审阅**：`npm run render:group` 出组级裁剪图；整页图由 `ppt_render` 出。
5. **`maturity`**：初版一律 `beta`；连续两轮真渲染无问题后升 `stable`。
6. **优雅降级**：空间不足/结构不合法 ⇒ 省略装饰并记 `notes`，或整体不产元素；**绝不产半成品**。

## 4. C1 过程中被机械判据抓出的真问题（值得后续复用）

1. **组容器与"组内折线"相交**：树的肘形连线 AABB 有高度 ⇒ 与容器判为意外重叠。修法：分组容器把**两端都在组内**的连线也纳入 `contains`（轴对齐直线 AABB 高度为 0，本来不受影响）。
2. **矩阵标题跑到安全区外**：标题原本放在 `box.y - 24`；改为**占画布内一条**（`titleH`）并把网格下移。
3. **断言侧**：IR 产出的 `line` **没有 `bounds`**（由 points 推导，schema 允许）⇒ 断言里必须自己按 points 求 AABB，否则每条线都被误判"越界"（真实门禁走的是正确路径，未受影响）。
