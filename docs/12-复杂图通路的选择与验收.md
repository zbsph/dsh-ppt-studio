# 复杂图通路的选择与验收

> 本文记录**为什么本插件采用「手写显式 elements + 门禁」这条通路**、它的等价性证据，以及回归基线机制。
> 早期设计记录中的方法论资产（真问题清单 / 止损判据 / 机械量化）摘录于文末。

## 1. 选择的通路

- 页面只用**显式 `elements`**：`shape`/`text`/`line`/`image`/`table`/`chart` + `bounds`/`points`/`kind`/`contains`/`attach`/`role`/`roleReason`；
- 引擎提供**机制**而不是模板：折线正交化、箭头前直段 ≥18px、`attach` 锚真实边缘（含斜边）、结构关系反验证、全部门禁检查；
- **不引入编译器**：没有"结构输入 → 自动布局"的一层。几何由作者显式给出，引擎只做后处理与校验。

## 2. 为什么不做编译器

- 编译器只能覆盖**枚举过的图形**；枚举之外要么降级、要么半成品 ⇒ 泛用性有硬上限；
- 一套编译器要自带审美与布局策略，改画法就得改代码 ⇒ 维护面扩大；
- 显式元素的表达力是**上界**：任何能被编译器产出的图，都能被显式元素写出来（反之不成立）；
- 代价（如实）：没有编译器 ⇒ 每页的坐标由作者给出，单页成本更高、批量大 deck 更慢。

## 3. 等价性证据（同内容严格对照）

| 判定 | 页数 | 说明 |
|---|---|---|
| 更好 | 10 | 02 03 04 05 07 09 10 11 12 13 |
| 持平 | 1 | 06 |
| 风格取向不同 | 2 | 01（是否加分组容器）、08（环用卡片还是真圆+编号点）—— **风格选择，不视为缺陷** |
| 变差 | **0** | —— |

门禁：13 页 **0 错**；机制（正交化/≥18px/attach/结构声明/检查）与既有实现**共用同一份代码**。

## 4. 回归基线机制

- `scripts/fixtures/handdrawn-baseline.json`：每页「元素 id+类型+圆整 bounds/points」规范化 JSON 的 sha256 + 每页错警计数 + 13 张 PNG sha；
- `npm run verify:handdrawn`：与基线比对（硬不变量 = layout 摘要；PNG sha 为次要不变量，差异只警告）；
- 几何若**确需变更**：`verify-handdrawn.mjs --capture --reason "原因"` ⇒ 保留 `history` 数组留痕（不许静默改基线）；
- 另三条手画护栏并入 `npm test`：`verify:redprobe`（6 条）/ `verify:linetext`（3 条）/ `verify:optionprobe`（2 条）。

## 6. 结构关系自动产出（阶段 A 的地基在这里被"用起来"）

| 关系 | 谁产出 | 说明 |
|---|---|---|
| `groups[]` | IR 的 `groups` | id 加前缀；成员 = 节点 id（含嵌套时按 IR 层次） |
| `element.contains[]` | 每个 `groups` 条目产出一个**容器 shape**，声明包含其成员 | 容器是几何真实的（包住成员，pad ≥ 6），因此几何反验证必然通过 |
| `element.attach{from,to}` | 每条 `edges` 产出一条 line，两端锚到节点边 | 方向决定 `side`（LR：右→左；TB：下→上）；因此**箭头必然落边**（阶段 A 的 `arrow-not-on-edge` 永不触发） |
| `expectedOverlaps` | 仅当引擎确实产出有意重叠时（本阶段：无） | 引擎不靠声明掩盖自身几何问题 |

**这条是阶段 B 的核心收益**：结构关系不再是"用户手写 + 引擎事后验证"，而是"引擎产出 + 用户可改"。

## 8. 硬门槛与回归门（沿用阶段 A 的四条 + 阶段 B 专属）

1. **确定性**：同一 deck 两次导出除 `core.xml` 时间戳外逐部件一致（含 IR 展开的 id 编号）；
2. **性能**：150 元素基线不退化（`scripts/bench-diagram-scale.mjs`）；新增"含 IR 的 150 节点页"基线（阶段 C 用）；
3. **判据严格性**：IR 校验与布局不变量的负面对照必须报红（自证脚本）；
4. **prompt 增幅 ≤5%**：`npm run probe:prompt:check`（阶段 B 若新增工具/参数必须复测）；
5. **无图页产物逐字节不变**：无 `diagram` 的页沿用阶段 A 的门控（`usesStructure`）与基线 tag 对照；
6. **预览↔成品同源**：由 §5 的结构保证（零改动）——自证脚本断言"预览 layout.json 的元素 == 导出消费的元素"。

## 4. C1 过程中被机械判据抓出的真问题（值得后续复用）

1. **组容器与"组内折线"相交**：树的肘形连线 AABB 有高度 ⇒ 与容器判为意外重叠。修法：分组容器把**两端都在组内**的连线也纳入 `contains`（轴对齐直线 AABB 高度为 0，本来不受影响）。
2. **矩阵标题跑到安全区外**：标题原本放在 `box.y - 24`；改为**占画布内一条**（`titleH`）并把网格下移。
3. **断言侧**：IR 产出的 `line` **没有 `bounds`**（由 points 推导，schema 允许）⇒ 断言里必须自己按 points 求 AABB，否则每条线都被误判"越界"（真实门禁走的是正确路径，未受影响）。
