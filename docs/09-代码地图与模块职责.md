# 09 · 代码地图与模块职责

> 目的：回答三个问题——**这个文件负责什么**、**改它会波及什么**、**改完该跑哪些测试**。
> 状态：随代码增删，**每次往 `src/` 加/删/挪模块时同步更新本文件**。
> 生成方式：`src/` 每个文件的首条模块注释 + 导出清单（本文件的表格由脚本与人工共同维护，避免与代码脱节）。

## 8. 新增模块的落位约定

- 引擎/DSL 相关 → `src/pptd/`（纯函数优先，便于单测）
- 门禁与审阅相关 → `src/verify.js` 或新增 `src/verify-*.js`
- 工具面 = `src/tools.js` 注册 + 描述；**不要**把业务逻辑塞进 `tools.js`（它只做校验、调度与文案）
- 能力探测/外部工具接入 → `src/capabilities.js` / `src/office-qa.js`
- 每个新模块必须在 §4 或 §5 的表里出现一行（否则视为"没有地图的模块"）

## 9. 白名单纪律：新增 DSL 字段必须改**三处**（阶段 A 踩了三次的坑）

归一化与快照都是**白名单式构造**（只挑自己认识的键），所以新字段不加进去就会**静默消失**——表现为"功能看着做了、跑起来全 0"。阶段 A 的 `contains/attach/badgeOf/roleReason/dash/arrow:'both'` 先后在这三处被吞：

| # | 位置 | 后果 | 本次修法 |
|---|---|---|---|
| ① | `src/pptd/layout.js` `normalizePage` | 新字段不进归一化元素 ⇒ 预览/导出/校验全看不到；`arrow: !!el.arrow` 还会把 `'both'` **压成 `true`**（两端箭头失效） | 逐字段透传；`arrow` 原样透传 |
| ② | `src/pptd/render-html.js` `snap()` | 字段不进 `layout.json` ⇒ **`ppt_verify`（吃 layout.json）里结构关系全为 0**，而性能数字照样好看 | 逐字段透传（含 `attachNotes`） |
| ③ | `src/pptd/import-pptx.js`（导入侧写 DSL） | 参考稿里的组合/容器信息在导入产物里丢失（阶段 D 才完整做） | 阶段 D 处理；现在导入只写基础字段 |

**纪律**：新增任何 DSL 字段时，同时改这三处 + 在 `scripts/smoke.mjs` §58 的"三处白名单透传"断言里加一行 + 在 `SCHEMA_REF`（`ppt_schema`，模型唯一的权威通道）里写一句。
**守卫**：`smoke §58`（透传断言）、`scripts/bench-diagram-scale.mjs`（"结构关系被真的用到"断言——它正是抓到 ② 的那条）。
