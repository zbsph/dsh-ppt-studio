# 10 · 宿主耦合点清单

> 目的：我们把"命"押在宿主（DSH）的哪些具体行为上。**升级 DSH 时逐条核对本表**（配合 docs/05「宿主升级纪律」）。
> 图例：**强**＝破了直接失效（有守卫）｜**中**＝破了会静默降级（需人工看）｜**弱**＝只是观察项。
> 证据里的宿主行号对应 **DSH 0.1.7-rc.2**（npm 全局安装 + 桌面端 asar 两处内容一致）；换版本后行号可能漂移，**以行为特征为准**。

## 3. 目录、运行时与外部工具

| # | 耦合点 | 我们依赖的具体行为 | 我们的位置 | 证据 | 破了会怎样 | 升级核对方式 |
|---|---|---|---|---|---|---|
| H11 | **`DSH_HOME` 与 profile 布局** | 用户数据在 `<DSH_HOME>/profiles/<name>/{package.json,node_modules}`；`dsh.profile.bundles` 决定自动入栈 | `src/home.js`、`cordis.patch.yml` | 实测（安装自证脚本） | **强**：找不到自己的状态目录 | `npm run test:bundle` |
| H12 | **`resources` 布局与 asar 锚点** | `<install>/resources/{app.asar, app.asar.unpacked, runtime/office-skills}`；插件可能跑在深层子进程 node 中 ⇒ 需**逐级上溯** | `src/capabilities.js`（`resourcesFrom`） | 桌面端实测 | **中**：探不到官方资产 ⇒ 静默少掉第三方自证 | 桌面端跑 `ppt_state` 看 `capabilities` |
| H13 | **primary-runtime 安装副本** | `<DSH_HOME>/dsh-runtimes/dsh-primary-runtime/**`（含 Python 与 Node） | `src/capabilities.js`（`primaryRuntimeRoots`） | 桌面端实测 | **中**：兜底引擎退回 PATH python（可能没有 python-pptx） | 同上 |
| H14 | **LibreOffice kit CLI 契约** | 子命令 `capabilities/convert/recalculate/render`；**输出目录必须不存在**（预建会 `EEXIST`）；`manifest.json` 提供 `images[].page`（原页号）与 `missingFonts` | `src/office-qa.js` | 桌面端实测（本轮踩过 EEXIST） | **中**：无 Office 时的真渲染降级失效 | 跑 `runLibreOfficeRender` 并检查 manifest |
| H15 | **官方 `check_office.py` 契约** | 位置 `<assets>/scripts/check_office.py`；`INPUT [--contains T] [--count N]`；stdout JSON `{format, verdict, checks, summary}`；退出码 0/1/2 | `src/office-qa.js` | 桌面端实测（verdict=pass） | **中**：第三方结构自证消失（会如实打印"未执行"） | 同上 |
| H16 | **捆绑 Python / Node 路径** | `<runtime>/dependencies/python/python.exe`、`…/node/node.exe` | `src/capabilities.js`、`src/pptxPy.js` | 桌面端实测 | **中**：兜底引擎与 kit 调用退化 | 看 `findPython()` 的 `source=bundled:*` |
| H17 | **技能目录约定** | `<plugin>/skills/<name>/SKILL.md`（front-matter + 正文；≤8000 字由我们自守） | `src/skill.js` | 宿主技能加载行为 | **强**：技能加载失败 | `npm test`（技能分节 + 字数断言） |
| H18 | **profile 管理权归属** | **`desktop` profile 由 Electron 应用独占**，CLI 明确拒绝 `--profile desktop` | 文档与流程 | CLI 实测报错 | **中**：桌面端只能走应用内插件管理或手动 pnpm | 见 docs/05「发布-同步纪律」 |

## 4. 外部依赖（非宿主，但同样会咬人）

| # | 依赖 | 行为 | 位置 | 破了会怎样 |
|---|---|---|---|---|
| E1 | **npm Trusted Publishing（OIDC）** | release 事件触发 → 下载 Release 资产 → OIDC `npm publish` → 发后自证 integrity；**无长期 token** | `.github/workflows/publish.yml` | 发布链路断（有手工补发入口） |

| E4 | **Node 内置模块** | 只用 `node:*`（无运行时依赖是纪律） | 全仓 | 新增依赖属"破坏纪律"，需用户批准 |
