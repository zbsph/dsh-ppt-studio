## [1.0.0 修订·标准安装姿势] 2026-09-14 —— `dsh plugin` **一条命令**即可安装（GitHub 资产 URL）；顺带修掉一个长期静默失效的路由 refcount

### 目的
用户问："市面上很多 dsh 插件都能用 npm 命令或 `dsh plugin` 命令安装，我们可以做到吗？"
先按 **A+B** 开工（bundle 安装 + 发布 npm），随后用户拍板：**"算了，只要确保用户能用 `dsh plugin` 一键安装就行"** ⇒ **放弃 npm 发布**，把力气全部放在"一条命令装好"这条路上。

### 1. 先查机制（不猜：harness 源码 + 真机实验两头验）
- `dsh plugin --profile <p> <args...>` 是**薄 pnpm 转发器**（`lib/plugin-*.js`）：在 profile 目录跑 pnpm，然后 `reconcilePlugins()` **按已安装状态**核对
  `dsh.profile.bundles`——**声明了 `dsh.bundle.patch` 的依赖自动进层栈**；没声明就只装不挂，并打一行
  `declares no dsh.bundle — installed as a plain dependency, not a profile layer`。
- 隔离 `DSH_HOME` 的"改动前"实验**复现了这句警告** ⇒ 证明本包此前用 `dsh plugin add` 装了也不生效。
  对 path/git/tarball 规格按**真实包名**入栈 ⇒ 从 GitHub Release 资产 URL 安装**不需要 npm 账号**。

### 2. 改动
- **`package.json`**：新增 `dsh.bundle.patch = ./cordis.patch.yml`；`cordis.patch.yml` 进 `files`；新增 `test:bundle` / `audit:facts` / `probe:effect` 脚本。
  **`private: true` 保持不动**（用户放弃 npm 发布 → 一键安装走 GitHub 资产 URL，不需要 npm 账号；发布步骤写在 README §10，将来要做再删它）。
- **新增仓库根 `cordis.patch.yml`**：`insert: [{id: ppt-studio, name: <包名>}]`，文件头写明**一条命令的安装 URL**与和 preset 行的**替代关系**。
- **装配防重（`src/index.js`）**：同进程第二次 `apply()` 只计数 + 告警、**不重复注册**（tools/commands/技能/监听器都是按名注册的服务）。
  用 `globalThis.__pptCoreReg` refcount（模块级变量在 junction/真实路径双加载下不可靠）。
- **新增自证脚本 `scripts/verify-bundle-install.mjs`（`npm run test:bundle`）**：隔离 `DSH_HOME` → 真 `dsh plugin add <spec>` → 断言
  "无 no-dsh.bundle 警告 / 已自动进 `dsh.profile.bundles` / 已物化 / `--dump-config` 出现 ppt-studio 行"。**不碰用户 profiles**。
  `spec` 缺省自己 `npm pack`（本地 tgz），也可传 **GitHub 资产 URL** 直接验"用户会敲的那条命令"。
- **改名防漂移**：`package.json.name` / `cordis.patch.yml` / 预设插件行三处由 smoke 断言钉住（改名漏一处 = "装了不生效/预设挂不上"的静默失败）。

### 3. 顺带修掉两个真 bug（都由本轮新增的**行为断言**当场抓出）
- **`ctx.effect` 语义**：用真库写最小探针实测——`ctx.effect(cb)` **立即执行 cb**，并以 **cb 的返回值**为 disposer（不是"cb 即清理函数"）。
  我新写的防重第一版写成 `ctx.effect(() => { count-- })` ⇒ **注册当刻就递减**，防重完全失效；smoke 新断言立刻报"首次 tools=21 / 二次 tools=42"。
  改成 `ctx.effect(() => () => { count-- })` 后转绿。
- **preview-server 的路由 refcount 一直是失效的**：同款写法 ⇒ 注册当刻 `count--` 并置 `cancelled = true`，
  文档承诺的"首个注册者真注册、最后卸载者真卸载"**从未成立**（路由注册后立即被取消）。已按真语义修正。
- **为什么长期没暴露**：smoke 里那个假 `ctx.effect` 把契约写反了（defer cb）——**假契约给真 bug 背了书**。
  已按真语义重写假 ctx；四条路由断言（幂等 / 单 dispose 不卸载 / 最后 dispose 卸载 / 残留表兜底）现在验的是真行为，全绿。

### 验证
- smoke **201 → 206 全绿**（新增 5 条：bundle 清单声明 / patch 名字与包名一致 / 保持 private（未发布）/ 三处包名一致 / **装配防重行为**）；
  **计数自证断言再次先红后绿**（一次点出 6 处引用并全部同步为 206）。
- **真机（两类 spec 都验）**：`npm run test:bundle` —— ① 本地 tgz 9/9；② **用户实际会敲的那条命令**（GitHub 资产 URL）见下方"安装验收"。
  e2e 13/13（真浏览器 + 真 Office）；preflight 11/11；check-preset 漂移 0；真实回归 2/0；手册事实审计 37/37。
- **安装验收（已实测 9/9，2026-09-14）**：隔离 `DSH_HOME` 下执行**用户实际会敲的那条命令**
  `dsh plugin --profile web add https://github.com/zbsph/dsh-ppt-studio/releases/download/v1.0.0/dsh-external-dsh-ppt-studio-1.0.0.tgz`
  → 退出码 0（pnpm 下载 58s）→ **无 `no dsh.bundle` 警告** → 依赖按 URL 规格记录 → **`dsh.profile.bundles` 自动含本包** →

  `node scripts/verify-bundle-install.mjs https://github.com/zbsph/dsh-ppt-studio/releases/download/v1.0.0/dsh-external-dsh-ppt-studio-1.0.0.tgz`

### 4. 顺手修的真 bug：导入侧 XML 实体解码缺失
- 做讲稿回环时发现：`<a:t>R&amp;D</a:t>` 导入后是字面 `R&amp;D`——**全仓库只有转义（导出侧），没有解码（导入侧）**。
  影响所有导入文本（`R&D` / `A<B` / 引号），一直存在，只是没被断言覆盖。

### 独立评审的 blocker：`role` 变更算不算绕过 content-collision（未采纳"删除路径"的处方）
- **指控**：`ppt-studio-data` §2 教的两条路（chart 加 `role: background` + 声明；或 `role: decoration`）都能让 `[✗] content-collision` 消失，
  而铁律 2 写着"内容互压不支持声明豁免，永远错误"——手册在教模型逃门禁。评审给了运行级证据（同一页三种 role 的 verify 结果）。
- **核查**：机制属实，但**"违规"的推论不成立**——铁律 2 自己就写了"纯装饰元素可加 `role: decoration` 豁免**重叠**（装饰性=设计意图声明）"，
  `SCHEMA_REF` 亦把 `decoration` 定义为"只豁免重叠"，而"文字压图片需声明"本就是本系统的标准姿势（图片的推断 role 就是 background）。
  也就是说：`role` 是**层叠语义声明**，不是豁免开关；把承载数据的图谎称背景才是错的。
- **处置**：**不改门禁语义**（改 = 影响既有工程与模板），改为在手册里把判据写死并封住懒用法：
  ① 先判"这张图承不承载结论"——承载 → **只有路径 A**（标签移出图框）；不承载 → 才轮到 B/C，且 B/C 是设计决定；
  ② 新增一句 **"`role` 不是消错开关"**（翻转 role 只为让报错消失 = 在输出上打补丁，craft §9-8 已禁）；
  ③ §7 报错表从"走 A 或 B"改成"先判图角色再选路径"；④ 张力入库为 **docs/01 C15**（含"若仍观察到翻转 role 逃门禁，再议纳入声明审计"）。

## [1.0.0 修订·撤回一条外部经验值] 2026-09-14 —— "明暗基调要换"是错的（用户抓到的原则冲突）

### 现象与根因
用户在 `ppt-studio-craft` §5 看到我写的一句："经验值（可覆盖）——同一套明暗基调（一直白底或一直深底）连续出现 3 页以上就该换"，

核查后确认这是我的失误，两处硬伤：
1. **说不出机制**（违反我刚写进 docs/05 §0 的"禁令准入判据"）：这条是从外部 skill 的调研报告里抄来的，
   既没有门禁、导出器或读入成本支撑，也不是任何工具会报的问题。

### 改动
1. **删除**该条经验值，改成正确口径：**"节奏靠密度与构图，不靠改底色"**——全册底色/主色/字体是主题的一部分，

   ② 原则闸（与我方门禁/原则冲突的一律不进，哪怕它在别处是主流做法）。本次失误即该条款的实例。

## [1.0.0 修订·连线二修] 2026-09-14 —— 箭头在 PowerPoint 里消失 + 水平连接线被画成斜线

### 现象（用户第二轮实测，同一份课件）
1. **箭头没了**：第 1 页三根"国力→晋"的箭头，网页预览有三角箭头，本地 PowerPoint 打开只有光秃秃的线（用户图 1↔2）。
2. **平的线变斜**：第 7 页卡片间的连接线，网页预览是水平短线，本地打开变成明显上斜的斜线（用户图 3↔4）。

### 根因（两个都在导出编码层，都是 OOXML 细节）
1. **`<a:tailEnd>` 被写在 `<a:ln>` 之外**。旧实现 `lineSpPr(...)` 已返回 `…</a:ln>`，之后又拼了一个 `<a:tailEnd/>`，
   它成了 `spPr` 的直接子元素——PowerPoint 只认 `<a:ln>` **内部**的线端设置，于是箭头被静默忽略
   （HTML 预览按 `arrow: true` 自己画 marker，所以预览没错）。
2. **包围盒被 `Math.max(1, |Δ|)` 兜底**。`straightConnector1` 画的是**包围盒对角线**：水平线源跨度 `cy=0` 被抬成 `cy=1pt`，
   一条 12pt×1pt 的对角线就是视觉上明显的斜线（预览按真端点画，所以平）。第 7 页连接线正是
   `points: [[216,228],[228,228]]` 这种 12pt 水平短线 → 中招。

### 改动
1. `lineSpPr(line, arrow)`：`<a:tailEnd>` 移入 `<a:ln>` 内（子元素顺序 fill → … → tailEnd 合规）；`connectorSp` 改传 `el.arrow`。
2. `connectorSp`：包围盒**精确**取线段跨度（不再 `max(1,…)`）——水平线 `cy=0`、垂直线 `cx=0`（Office 自己也这么写，合法）；
   仅"零长线"（两端重合）给 1×1 兜底，免被消费端丢弃。
3. 自证扩展：`proof` 增加"arrow=true 时 `<a:tailEnd>` 必须在 `<a:ln>` 内"，并入 `parity.linesWrong`（→ `parity.ok`）。
4. 顺带修自检脆弱性：smoke 的两处 Office COM 实测改为**抖动降级**（PowerPoint 正开着文件/弹对话框时 COM 会临时不可用，
   旧代码会让整个 smoke 崩掉——本轮就撞上了），打印 ⚠ 并按"降级跳过"记通过，符合"Office 是可选增强"的既定语义。

  结构断言：水平线 `ext=(152400,0)`（=12pt×0）、垂直线 `ext=(0,2540000)`、斜线精确等于跨度、零长线 1×1、箭头在 `<a:ln>` 内。

## [1.0.0 修订·连线方向] 2026-09-14 —— 网页预览对、PowerPoint 里线条镜像 / × 少一笔（导出几何丢方向）

### 现象
用户实测（三国课件 21 页）反馈：`ppt_preview` 网页预览正常，但**打开导出的 .pptx** 时线条不对——
第 5 页「皇帝 → 宗室」的斜线方向反了、红色 × 只剩一笔（用户截图对比 1↔3）；第 6 页阶梯图的竖向连接线消失/错位（2↔4）。

### 根因
`connectorSp()` 把连线写成 `p:cxnSp` + `prstGeom prst="straightConnector1"`，几何只给包围盒 `off/ext`。
但 `straightConnector1` 在 OOXML 里**只按包围盒的左上→右下绘制**——线的真实走向必须由 `flipH`/`flipV` 表达，
旧实现两个属性都没写。后果：
- `Δx>0, Δy<0`（右上）与 `Δx<0, Δy>0`（左下）的线**斜率被镜像**；
- 一组交叉线（× 的两笔）方向相反时，缺 `flipH` 会让两笔**完全重合**成一条 `/`——正是截图里那个"小短杠"。

用用户自己的产物取证：`slide5.xml` 里 `cut: off=(352,172) ext=(82x36) flip=(无)`——源是 `[434,172]→[352,208]`（左下），
导出却画成左上→右下；`cross1`/`cross2` 两条几何完全相同（都是 `off=(344,208) ext=(14x14)`、无 flip）。
HTML 预览走 render-html.js（按真端点画 SVG），所以预览一直是对的——**问题只在这一层编码**。

### 改动
1. `connectorSp()`：按 `p2` 相对 `p1` 的方位补 `flipH`（p2 在左）与 `flipV`（p2 在上）；`tailEnd`（箭头）始终落在画出的终点＝ `p2`，方向自动正确。`xfrm()` 增可选 `flips` 参数。
2. **导出自证升级为"逐条连线反推端点"**：新增 `connectorEndsFromXml()`，从写出的 XML 反解 OOXML 语义端点并与源 `points` 逐条比对
   （退化轴因包围盒下限 `max(1,…)` 放行 ≤1pt，其余 ≤0.01pt）；不一致计入 `parity.linesWrong` 且 `parity.ok=false`；
   `ppt_export` 的 parity 行现在会打印"线方向 N/N"。这把"预览对、成品错"这类**跨层不一致**变成机器可拦。
3. 回归：smoke 新增 §34（四方向 + 箭头 + × 两笔 + parity 自证，7 断言 → 163 全绿）；e2e 新增 parity/线方向断言（→ 13 全绿）。
4. 文档：README FAQ 增该现象与处置（旧产物需重新 `ppt_export`）；docs/02 §2.7 记录 flip 语义与自证机制；手册 skill 同步。

### 验证
- 用用户那份 deck 重导：`parity = {tables 3/3, images 0/0, lines 67/67, linesWrong 0, ok:true}`；修复前同一份 deck 有 **51 条**方向错。
- **Office COM 真渲染**第 5/6 页人眼复核：斜线方向、红色 ×、阶梯竖线全部与网页预览一致。
- smoke 156 → **163**；preflight 11；e2e 12 → **13**。

### 影响/后续
- **修复前导出的含斜线/箭头/× 元素的产物需重新导出**（水平/垂直/右下方向的线本来正确，建议整册重导统一）。
- 版本号保持 1.0.0（用户指示）；同 tag 资产原地更新。

## [0.3.2] 2026-09-04 —— C3 修订为"出界分级声明制" + D1–D6 全部落地

### 目的
用户对 C3 提出关键设计观点：**与其"角色豁免"（decoration 全豁免出界），不如与重叠同构的"声明制"**——设计时把有意落在页眉页脚带的元素列为"意料之内"，审阅时对照，命中即（确认）通过，未命中即错。设计者必须逐元素思考"这是否合理"，而不是贴个角色标签就不管了（后者正是 C2 担忧的放大版）。同时 D1–D6（意图自证/audit 范围/实测档关系/安全区探测/性能/发布）按用户认可的倾向落地。

### 改动
1. **出界分级声明制（C3 修订）**：
   - 新页级字段 `expectedOutOfSafeArea: [idA, ...]`：有意落在模板页眉页脚带/安全区外的元素，**逐元素手工声明**；id 必须存在于本页（schema 防呆，声明无效当场报错）。
   - verify 分级：超**页面边界**=永远 ERROR（不可声明）；超**安全区**（仍在页面内）=声明制——命中 → confirmed（✓ 预期出界，计数入报告头），未命中 → ERROR（错误信息指向如何声明）。
   - **回滚 v0.3.1 的 decoration 豁免出界**：`role: decoration` 收窄为只豁免重叠（"装饰性"本身是设计意图声明）；页眉页脚带元素走 expectedOutOfSafeArea。
   - autoDeclare **不自动生成出界声明**（出界=个案思考，与批量重叠声明分工）。
2. **D1 意图自证**：提示词（铁律 2 尾 + 入门段）规定 autoDeclare 写入后输出声明清单，每对附一句意图；说不清意图的对子必须改布局而不是声明。SCHEMA_REF 同步。
3. **D2 audit 档补完**：`ppt_export` 在 audit 档自动追加**回读断言**（产物 OOXML：页数/尺寸精确 EMU/最小字号 ≥ minFontSize），报告逐项 ✓/✗；提示词铁律 11 规定 audit 行为（禁 autoDeclare、强制 shot+读图、核对回读断言、素材来源标注）。
4. **D4 导入安全区探测**：`detectBands` 统计跨页重复元素（≥60% 页数同位置）→ 顶部/底部带 → deck.yaml 写入注释 `# safeArea: {top, bottom}`（**不自动启用**）+ 导入报告提示。
5. **D3/D5/D6**：决策记录（docs/01 §6）。

### 验证
- smoke 51 → **60 断言**（+9：未声明出界含 decoration 报错、超页报错、一级声明命中 confirmed、声明后 decoBand 消错、超页声明无效仍错、坏 id 防呆、D4 带探测回环、重验计数与错误集合）。
- 全量 smoke 全绿；回归脚本不动（WPS fixture 2 页 < 3 页不触发带探测，符合设计）。

### 影响 / 后续
- 语义统一为"空间断言 = 设计意图声明制"（重叠 + 安全区出界两个维度），角色制只剩 decoration 的重叠豁免。
- C11（出血 bleed）记入争议清单：超页不可声明是一致性代价，真实需求出现时再议。
