## 1. DSL 字段草案

### 1.1 新增/扩展字段一览

| 字段 | 位置 | 必填 | 语义 | 校验强度 |
|---|---|---|---|---|
| `groups[]` | page | 可选 | 逻辑分组（可嵌套），剪枝/审阅/声明的作用域 | schema 错误 |
| `groups[].id` | — | 必填 | 页内唯一；**与元素 id 共用同一命名空间** | schema 错误 |
| `groups[].label` | — | 可选 | 人类可读用途，出现在审阅输出里 | — |
| `groups[].members` | — | 必填 | 元素 id 或**嵌套组 id** | 存在性/无环/唯一归属 |
| `element.contains[]` | element | 可选 | 该元素是这些元素的**视觉容器** | 几何反验证 |
| `element.attach` | line | 可选 | `{from: {ref, side}, to: {ref, side}}`，导出/测量时解析成边上的点 | 几何反验证 |
| `element.badgeOf` | element | 可选 | 该元素是那个元素的**徽章/标签**（压在边上或局部覆盖） | 几何反验证 |
| `element.roleReason` | element | 条件必填 | 当 `role` **覆盖**了推断值时必须给理由 | 缺失 ⇒ 警告 |
| `expectedOverlaps[].reason` | page | 建议必填 | 既有字段扩展：为"有意重叠"补上**机器可读的理由** | 缺失 ⇒ 警告 |

`side ∈ {top, right, bottom, left}`；`role ∈ {background, content, decoration}`（既有）。

### 1.2 关于 `expectedIntersections`（对 docs/07 §9.5 的收敛）

docs/07 §9.5 写的 `expectedIntersections: [{from, to, reason}]` **不再新增字段**，改为**扩展既有 `expectedOverlaps`**：

```yaml
expectedOverlaps:
  - {pair: [chip_A, card_B], reason: "A 的徽章压在 B 的卡片上（设计意图）"}
```

理由：① 两者语义完全相同（"允许这两个相交"），并存会出现两套豁免机制；② `expectedOverlaps` 已经在 schema/verify/闭包里实现并被既有测试覆盖，扩展 `reason` 是**向后兼容的纯增量**；③ 组的作用域由 `groups` 提供，不需要第二个字段承载。
补强（本条是新能力）：**跨组声明要额外校验**——若 `pair` 两端分属不同组，则必须能通过 §2 的"确实相交"谓词；否则按普通重叠处理。**【待确认】**

### 1.3 示例

```yaml
pageType: content
groups:
  - {id: g_in, label: 输入层块, members: [in_box, in_txt]}
  - {id: g_core, label: 仿真内核块, members: [m1, m2, m3, g_loop]}
  - {id: g_loop, label: 迭代反馈小块, members: [loop_line, loop_txt]}
elements:
  - elementId: zone
    elementType: shape
    kind: roundRect
    bounds: [40, 120, 880, 300]
    contains: [in_box, in_txt, m1, m2, m3]
    role: background
  - elementId: in_box
    elementType: shape
    kind: parallelogram
    bounds: [70, 200, 180, 90]
  - elementId: chip
    elementType: shape
    kind: roundRect
    bounds: [300, 130, 120, 34]
    badgeOf: zone
    role: background
    roleReason: "作为 zone 的标题胶囊"
  - elementId: e1
    elementType: line
    attach: {from: {ref: in_box, side: right}, to: {ref: m1, side: left}}
    arrow: end
    line: {color: "#1F2937", width: 1, dash: solid}
expectedOverlaps:
  - {pair: [chip, zone], reason: "标题胶囊故意压在容器顶边"}
```

## 2. 结构关系：严格判据与"反验证"

**总原则：声明本身不是豁免，声明 + 通过几何反验证才是豁免。** 任一条关系不成立 ⇒ 该关系**作废**，并按普通冲突处理，同时给出一条点名声明不成立的错误。

| 关系 | 严格谓词 | 不成立时 |
|---|---|---|
| **包含** `contains` | 对每个 child：`child.x ≥ parent.x + pad` ∧ `child.y ≥ parent.y + pad` ∧ `child.right ≤ parent.right − pad` ∧ `child.bottom ≤ parent.bottom − pad`（`pad` 默认 0） | 错误 `contains-unsatisfied`（点名 parent/child 与溢出量） |
| **附着** `attach` | 端点落在目标**对应边**上：`side=right` ⇒ \|x − ref.right\| ≤ tol ∧ `ref.y ≤ y ≤ ref.bottom`；其余边同构（`tol` 默认 **1.5px**） | 错误 `attach-unsatisfied`（点名 ref/side 与实际落点） |
| **徽章** `badgeOf` | ① chip 与 owner **确实相交**（交叠面积 > 0）② chip 面积 ≤ owner 面积 × **0.5** ③ chip 不完全覆盖 owner（owner 至少 1 个角在 chip 之外） | 声明作废；按普通重叠处理并提示"这更像遮罩而非徽章" |
| **组** `groups` | 成员存在；无重复成员；嵌套**无环**；一个元素**只能属于一个直接组** | schema 错误 |
| **有意重叠** `expectedOverlaps` | 两端存在；**确实相交**（否则 ℹ 提示"声明已失效"）；两端不得同时是 `content`（`content × content` 永不放行） | 存在性/类型 ⇒ schema 错误；不相交 ⇒ ℹ |

**容差与 pad 的默认值**写进 `ppt_schema` 速查，并允许 page 级覆盖（`relationTolerance: {pad, tol}`）。**【待确认：默认值是否合适，需用真实稿校准】**

### 2.1 推导结果不落盘

由结构关系**推导出的豁免对**（例如"容器 ⊇ 子元素"隐含的那些 pair）**每次运行时计算、不写回 deck.yaml**。理由：一旦落盘，引擎的一次 bug 会被固化成数据（之后永远豁免），违反"不静默"。

## 3. 新增的图专属校验（无声明也要查）

| 检查 | 判据 | 级别 | 可声明豁免？ |
|---|---|---|---|
| `duplicate-element` | 同 kind + 包围盒差 < **2px**（或完全重合） | **ERROR** | 否 |
| `text-over-text` | 两个 `role: content` 的**文本**元素相交（容差 1px） | **ERROR** | **永不**（既有规则沿用） |
| `line-through-box` | 线段几何路径穿过**非端点**元素内部（留 tol） | **ERROR** | 否 |
| `arrow-not-on-edge` | `arrow` 端未接触任何元素边界（tol 1.5px） | WARNING（提示可能脱靶）；**若同时有 `attach` ⇒ ERROR** | 否 |
| `group-invariant` | 同组内元素应共享对齐/节奏（B 阶段细化；A 只做"组内元素是否落在同一条网格线上"的提示） | WARNING | 否 |

> `content × content`、超页面边界仍**永远不可声明**（既有规则不动）。

## 4. 实现：模块、数据流、确定性

### 4.1 新增模块 `src/pptd/relations.js`（纯函数，可单测）

```
输入：normalizedPage（元素已归一 + 声明字段）
输出：{
  groups:      [{id, label, members, depth}],            // 展开后的组树
  relations:   [{type: 'contains'|'attach'|'badge'|'overlapDecl', from, to, valid: bool, evidence, reason}],
  exempt:      Set<'a×b'>,                                // 由**有效**关系推导出的豁免对（排序键）
  invalid:     [{type, from, to, why}],                    // 声明不成立的清单（转错误）
  stats:       {contains: n, attach: n, badge: n, groups: n, exempt: n}
}
```
**确定性要求**：全部输出按 id 字典序排序；不使用随机、不使用时间；同一输入两次调用 ⇒ 深度相等（加断言）。

### 4.2 数据流

```
resolveDeck → normalizePage
   → relations.derive()            （新：结构关系 + 反验证 + 豁免集）
   → resolveAttach()               （新：把 attach 解析成 points / 折线）
   → verify.js                     （改：吃 exempt/relations，产出新报告）
   → export-pptx.js                （改：折线/箭头/虚线/prst 直通）
   → measure/preview/shot          （不改逻辑；折线与箭头沿用同一几何）
```

### 4.3 与既有机制的关系（全部复用，不重造）

| 既有机制 | 本阶段如何使用 |
|---|---|
| `role` 三值 + 推断 | 不变；新增 `roleReason`（覆盖时必填理由） |
| `decoration` 完全豁免 | 不变 |
| `expectedOverlaps` + `buildDeclaredSet` + 传递闭包 | 扩展 `reason`；**闭包继续只沿包含链传播，不沿"跨组声明"传播**（加断言） |
| 同源 id 前缀豁免 | 不变；`groups` 的成员天然共享前缀时可复用 |
| 超页面不可声明 / 超安全区声明制 | 不变 |

## 5. 报告形态（聚合 + 真冲突单列）

```
门禁：✗ 2 个错误（必须清零）
结构关系：组 4｜包含 5｜附着 6｜徽章 1（自动豁免重叠 12 处，未落盘）
意外冲突（2 —— 必须修正）：
  ✗ duplicate-element｜"box3" 与 "box7" 几乎重合（Δ<2px）
  ✗ line-through-box｜"e2" 穿过 "box5"
设计声明复核：
  expectedOverlaps 3 处（其中 1 处已失效：["e9","t4"] 已不相交 ⇒ 建议移除）
  role 覆盖 2 处（chip→background：作为 zone 标题胶囊｜zone→background：容器底）
  attach 声明 6 处全部成立（tol 1.5px）
提示（warning 级，不影响门禁）：arrow 端未落边 1 处（"e7" 末端）｜组内网格不一致 1 处（g_core）
```

规则：
1. **真冲突永远单独列出**，不做聚合；结构关系只计数。
2. 报告默认**上限 30 行**，超出折叠为"…另有 N 条，用 `detail` 重跑查看"。
3. **声明复核段固定存在**（哪怕为空也要打印"声明复核：无"），确保"豁免可见"。

## 6. 导出/测量的最小扩展

| 项 | 设计 | 不变量 |
|---|---|---|
| `attach` 解析 | 在归一后、导出前把 `attach` 解析为 `points`（直线两点的情形）；`side` 相对时用 **L 型单拐**：先沿 from 的法向出 12px，再水平/垂直到 to 的法向入 12px | 与手写 `points` 同时存在 ⇒ **`attach` 优先**并在报告提示 |
| >2 点折线 | 导出为 **custGeom 开放路径**（`moveTo` + `lnTo`…，不 `close`），带描边、无填充；箭头挂在该路径的 `a:ln.tailEnd/headEnd` | 若开放路径在我们的 custGeom 写盘器上不支持 ⇒ **退化为 N 条直线**（相邻端点重叠 1px 去缝），并记录降级 |
| 箭头两端 | `arrow: true｜'end'｜'both'`（`true` 等价 `'end'`，向后兼容） | 既有 `arrow: true` 产物不变 |
| 虚线 | `line.dash: solid｜dash｜dot｜dashDot`（缺省 solid） | 既有产物不变 |
| prst 补齐 | `SHAPE_KINDS` 追加 `notchedRightArrow`（含导出的 prst 直通与导入保留） | 既有产物不变 |

**验收方式**：以上每一项都配"用了该字段"与"没用该字段"两个夹具；后者产物**逐字节不变**。
