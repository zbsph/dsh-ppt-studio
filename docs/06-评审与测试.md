## 一、五原则审查

### 1.1 鲁棒性（适应不同用户/场景）—— 评级：良好（有明确边界）

**已具备的防线**：

| 维度 | 机制 |
|---|---|
| 能力探测 | Office / Edge / python 全部探测后降级（无浏览器→标注"未实测/未经视觉审阅"；无 Office→真渲染通道自动隐藏；无 python→兜底链路不可用提示） |
| 引擎回退 | auto=pptd 主引擎；硬失败→python-pptx 兜底**醒目标注**；显式指定引擎绝不静默降级 |
| 文件兼容 | UTF-8/UTF-16（WPS）XML 自动识别；store/deflate zip；媒体缺失→占位图（导入/导出双侧） |
| 坏输入 | 缺 deck.yaml / YAML 语法错误（附笔误指引）/ 元素级样式键 / 声明 id 防呆 / 空 pages / 0 元素页 / 2000 字长文——preflight A1-A6 全绿：**报错不崩溃，且报错带指引** |
| 幂等 | 路由（双源单装配 + refcount + 表判据）、autoDeclare、重复导出、重复 splice |

**已知边界（诚实声明，均有替代路径）**：字体观感假设（估算档；加粗 CJK 已×1.06 补偿）；EMF 媒体；跨平台（COM/Edge 探测面向 Windows）；pptxgenjs 未实现（D6 决策）；动画/阴影/超链接/母版继承不导入。**跨用户风险**：新用户首次遇到的"隐形契约"（样式键层级）已由 ppt_check 报错 + 手册 + skill 覆盖。

### 1.2 泛用性（功能/场景覆盖）—— 评级：良好（主线全覆盖，纵深有边界）

- 四类任务（from-scratch/augment/edit/summarize）语义路由 + quick/normal/audit 三档。
- 保真三通道（参考双轨 / 手术 patch / 替换 splice+slice）——"像 / 贴 / 保"全覆盖。
- 输入：.pptx 导入（参考层 + 全量色板 + safeArea 探测）；图表（bar/line/pie 矢量拼绘）；custGeom/渐变/alpha/prst。

- **E2E 佐证**：自建高难度夹具 12 页（声明制/安全区/渐变/alpha/custGeom/嵌套卡/表格/图表/跨页数字/来源标注）门禁 0 错误。

### 1.3 可维护性 —— 评级：优秀（本轮再加固）

## 四、核心亮点（1.0.0 叙事）

1. **声明制（设计意图）胜过元素类型制**：唯一让"有意叠层"合法的方式；content-collision 硬底线 + 声明闭包 + autoDeclare。这是"避免元素区块冲突"的机器化答案。
2. **可验证的生产线（三轨）**：数字门禁（快）/ 视觉审阅（慢但必要）/ Office 真渲染（有条件终极真值）+ M2 浏览器实测=终审——"质量不是靠运气"。
3. **保真交付一个命令**：splice（替换进原稿，其余页 SHA256 逐字节自证）/ slice（单页+完整母版）/ patch（贴模板）——"编辑既有精美 PPT"从手工 zip 手术变成工具。
4. **自包含范例生态**：内置模板（4 版权自研 + 外部模板双轨）、ppt_new 样例、examples/fx 高难度夹具——新人可学、可验、可复现。

## 七、内置技能的对照评测（2026-09-14）

### 7.1 方法
- **两臂只切换插件包来源**：A = 当时发布版（`D:\plugins\package`，**无**三本新技能，工作流提示词无新指引行）；B = 源码版（含三本技能 + 一行"何时加载"指引）。
- 输入为**同一份 `brief.md`**（把 6 条原始记录整理成 5 页汇报 + 导出 pptx），同一台机器、同一模型、同一 headless 装配（`dsh --profile headless --patch <overlay>`），两臂各跑 **2 轮**。
- 门禁指标由**同一个 lib**事后复算（`resolveDeck → renderDeck → verifyDeck`），避免"自己评自己"。
- 指标：元素数 / 文本字数 / 图表表格数 / `[✗]`错误 / `[⚠]`警告 / `[·]`建议 / AI 味信号命中数（按 `ppt-studio-copy` §4-5 的信号表扫描页面文本）/ 标注来源的页数。

### 7.2 结果

**有效轮次**（A = 无新技能、工作流无新指引行；B = 含 4 本内嵌技能 + 指引行）：

| 指标 | R1 A | R1 B | R3 A（as-shipped） | R3 B（as-shipped） |
|---|---|---|---|---|
| 元素数 | 103 | 92 | 94 | **85** |
| 文本总字数 | 1202 | **1073** | 1524 | **860** |
| 图表 / 表格 | 0 / 1 | 0 / 1 | 1 / 1 | 0 / 0 |
| `[✗]` 错误 | 0 | 0 | 0 | 0 |
| `[·]` 建议 | 12 | **8** | 13 | 14 |
| AI 味信号命中 | 1 | 1 | 0 | 0 |
| 标注 `source:` 的页数 | 5 | 5 | 5 | 5 |

**结论（按证据强度排序）**：
1. **没有回退**：两轮有效对照里，B 在全部指标上都不比 A 差（建议项 R1 更少、R3 持平；文本量两轮都显著更少）。
2. **文本更省**：−11%（R1）与 −44%（R3）——与"页面文字是结论+证据，解释进讲稿"的定位一致。
3. **一处定性改进**（R1 人工比对）：B 把"行业报告显示…专家认为…"改写成页内**「来源提醒」**（"没有机构、样本量与年份，对外引用前必须补上"）并在 `source:` 写明"暂不可对外引用"；A 把这句原样搬进了页面。
4. **不要夸大的部分**：门禁错误四臂全为 0——差异在**风格与冗余度**，不是"过不过门禁"。这与用户自己的判断一致：技能是**锦上添花**，不是质量闸门。
5. 技能真正的不可替代价值，是**基座模型无从知道的插件事实**（例如"导出的 pptx 里 chart 只画几何、没有标签"），这类内容 A 臂无从获得。

**无效/受污染的轮次（如实记录）**：
- R2：A 臂跑之前，B 臂的 `install.mjs` 已把新技能镜像到 `<dshHome>/skills/`，**A 臂也能看到技能**（transcript 命中技能名）→ 不是"before/after"，作废。
- R3-first-attempt：同样受镜像污染，且 arm A 包由 `git archive` 构造时丢了 `lib/`（被 gitignore），未真正运行 → 作废。
- 受污染轮次仍有一条有用的副产物：**它证明文件镜像通道有效**——即使插件包内没有技能，模型也会从 `~/.dsh/skills/` 拿到同名技能。

**定性差异**（人工比对两臂产物原文）：
- B 臂把材料里的模糊归因（"行业报告显示…专家认为…"）改写成页内**「来源提醒」**（"没有机构、样本量与年份，对外引用前必须补上"），并在 `source:` 写明"暂不可对外引用"；A 臂把这句原样搬进了页面。
- B 臂页标题更常写成"**结论 + 影响/动作**"（如"团队 6 人下月只剩 4 人，11 月后人均要覆盖 1.5 个园区"），A 臂更常是"栏目名：事实"（如"进度与团队：2 个园区待接入"）。
- B 臂有一页显式标注图表口径（"柱长按 100% 等比缩放"）。

### 7.3 诚实边界
- **n=2 有效轮次、单一 brief**：这是方向性证据，不是统计结论；且**没有出现"全指标一致更优"**，只有"不回退 + 文本更省 + 一处定性改进"。
- 所有有效轮次 `[✗]` 都是 0——差异出现在**风格/冗余度**，不是门禁通过率。
- 评测跑在**评审修补之前**的版本上；评审后的改动是标注与措辞收敛（不影响上述行为差异）。
- AI 味信号用短语扫描做粗度量：两臂都可能命中同一个短语而**处理方式完全不同**（A 复述 / B 标注），计数需与定性读法一起看。
- **对照实验的污染源（本轮实测发现）**：技能有两条交付通道——**内嵌注册**（插件层）与**文件镜像**（`<dshHome>/skills/`，全局层）。
  只要机器上跑过一次新版 `install.mjs`，镜像就会让**两臂都能看到**新技能，A 臂不再"无技能"（R2 与 R3 第一次尝试都栽在这）。
  干净做法：跑 A 臂前把 `~/.dsh/skills/ppt-studio-{craft,data,copy}` 移走，跑完再恢复；否则只能得到"上界"而非"增量"。
  更稳的造包方式见 §7.5：**用普通复制 + 手工删技能/删指引行**，不要用 `install.mjs` 造对照包（它会建 junction）。

### 7.4 独立评审（同轮）
三本技能另交独立评审员逐条对照源码核对，发现 7 类真实缺陷并全部修补（清单见 `docs/03` 同日条目）。
结论：**机器守卫能挡住"写死数值"，挡不住"语义偏移/不可执行/重复"——两者必须并存**（已写入 docs/05 纪律）。

**第二轮（2026-09-14 全面自检）**：用户要求"充分完善的自检"，于是同一套协议再跑一次，但这次是**四本手册全量**、且要求每条缺陷给**两侧 file:line 证据**、
并把"确认缺陷"与"存疑待验"分开写。结果：**1 blocker + 6 major + 11 minor + 8 条无机制经验值 + 4 条源码侧缺陷**（处置清单见 `docs/03` 同日条目）。
两条方法论收获：
- **blocker 也可能被判错**：评审把 data §2 的 `role: background/decoration` 判为"教模型逃 content-collision"，
  但铁律 2 自己就写了"纯装饰元素可加 `role: decoration` 豁免**重叠**"——`role` 是层叠语义声明而非豁免开关，
  故**不采纳"删除路径"的处方**，改为把判据写死（承载结论 → 只能 A）+ 明写"`role` 不是消错开关"，张力入库 docs/01 C15。
  **独立评审的价值在"证据"，结论仍要自己复核**——照单全收会把手册砍得更差。
- **证据必须落在字节上**：评审自述它对 `skills/*` 的**首次读取拿到的是旧版本**（read 缓存），它是靠 node 按字节复核才定稿的。
  凡"手册 vs 源码"的结论（含本仓库自己的自检），都要以**当次读取的字节/哈希**为准，不能只信一次读取。
- 本轮之后，"工具名/错误码/严重度标记/DSL 形状/预览阈值/引用计数"六类已进机器防线（smoke §37/§38，13 条）；§7.4 仍需覆盖"裸阈值当建议写、语义偏移、不可执行指令、跨本重复"。

### 7.5 复现方法（随包提供两个脚本）
```powershell
# ① 造"前一版"包：**普通复制**当前包，再删掉新技能与工作流指引行（不要用 install.mjs，它会建 junction）
#    记得带上 node_modules/yaml（install.mjs 平时负责这一步）
Copy-Item <repo>\{lib,skills,templates,scripts,docs,agent-presets,package.json,README.md} <tmpA>\ -Recurse
Copy-Item <repo>\node_modules\yaml <tmpA>\node_modules\yaml -Recurse
Remove-Item <tmpA>\skills\ppt-studio-{craft,data,copy} -Recurse
#    删掉 lib/router.js 里含 ppt-studio-craft 的那一行（≈186 字符）
# ② 跑 A 臂前移走技能镜像（否则 A 也能看到技能）
Move-Item $env:USERPROFILE\.dsh\skills\ppt-studio-{craft,data,copy} <backup>\
cmd /c rmdir <profile>\node_modules\@dsh-external\dsh-ppt-studio   # 只用 rmdir，不要 Remove-Item -Recurse
cmd /c mklink /J <profile>\node_modules\@dsh-external\dsh-ppt-studio <tmpA>
dsh --profile headless --patch <overlay.yml> "<任务>"              # A 臂
# ③ B 臂：junction 改指 repo，重跑同一任务
# ④ 恢复镜像、删 junction，然后同口径复算 + 生成盲评材料：
node scripts/eval-skills-score.mjs --a <deckA> --b <deckB> --out RESULT.md
node scripts/eval-skills-blind.mjs <deckA> <deckB> --out <盲评目录>
```

### 7.6 结构化盲评（协议 + 结果）
**协议**（为什么必须盲：技能是"软收益"，自评必然有偏；且两份产物的目录名/命名习惯会泄露来源）：
1. 用 `scripts/eval-skills-blind.mjs` 把两臂产物**匿名化 + 随机分配**成「盲评-1 / 盲评-2」，真实映射只写进 `mapping.json`（不给评审员）。
2. 材料只含**产物本身**：源描述 `deck.yaml + pages/*.yaml` + Office 真渲染整页 PNG（不含 transcript、不含任何生成过程记录）。
3. 评审员（独立 agent）按**固定 6 维**打分并给证据：叙事结构 / 标题质量 / 信息密度与可读性 / 数据呈现 / 版式与视觉一致性 / 文案；每维 1–5 分，必须引"第几页、哪句话"。
4. 评审员**不得猜测来源**；最后给总分、更适合交付的一份、以及"把握度 + 不确定在哪"。
5. 结果落档后**再揭示映射**（避免事后编故事）。

**结果（2026-09-14，R4 两臂产物）**：`盲评-1 = B（含技能）`、`盲评-2 = A（无技能）`（映射见当轮 `mapping.json`）。

| 维度 | 盲评-1（**B 含技能**） | 盲评-2（A 无技能） |
|---|---|---|
| 叙事结构 | 4 | 3 |
| 标题质量 | **5** | 4 |
| 信息密度与可读性 | 4 | 4 |
| 数据呈现 | 4 | 4 |
| 版式与视觉一致性 | 4 | 4 |
| 文案 | **5** | 3 |
| **合计** | **26 / 30** | 22 / 30 |

**独立结论**：更适合直接交付的是**盲评-1（含技能）**。评审员给的三条关键证据，正好命中三本技能的原定目标：
- 标题 5/5："五条全是带数字的结论句、无栏目名…只读标题即得结论链"（`ppt-studio-craft` §4）；
- 文案 5/5："无排比/破折号/升华；材料 4 的'里程碑·重塑'改成可核对句"（`ppt-studio-copy` §2/§4）；
- 数据 4/4 的关键加分："第 3 页把'93% vs 78%'的口径不可比写在页面上（'此处只作并列对照'），并注明 78% 报告名/样本未注、专家评价仅转述"（`ppt-studio-data` §3）。
- 反过来，A 臂被指出**夹了一句材料里没有的结论**（"系统已承接大部分重复巡检工作"）——正是 `ppt-studio-copy §2 只改文风不动事实` 要挡的失效模式。

**两点说明（用户事后判定，已据此修订技能）**：
- 评审员把"含技能那份第 2 页柱图没有类别/数值标签"当作硬伤、把"无技能那份标全了"当作优点——这**不是**缺陷判定：
  图表常常就是装饰/示意/背景，本来就不需要标签。已把 `ppt-studio-data` §0 从"交付级图表必须补标签"改成
  **"先分清这张图是证据还是装饰"**的判据（承载数据 → 标签四件齐；装饰性 → 允许无标签，但交付说明标注"仅作示意"、页面结论不得依赖它），
  并**撤销**了"给 `ppt_verify` 加图表标签建议"的候选（不把风格偏好变成机器提示）。
- 同理，评审员的"该拆/该合""该不该有标签"这类判断都属**内容量/风格判断**，不是门禁口径；本条结论只作方向性参考。

**把握度**：评审员自评"中"，不确定处：小字（12pt）靠预览辨认可能误读；页数无硬性上限时"该拆/该合"属内容量判断；未见讲稿备注。
