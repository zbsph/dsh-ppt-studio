## 一、五原则审查

### 1.1 鲁棒性（适应不同用户/场景）—— 评级：良好（有明确边界）

**已具备的防线**：

| 维度 | 机制 |
|---|---|
| 能力探测 | Office / Edge / python 全部探测后降级（无浏览器→标注"未实测/未经视觉审阅"；无 Office→真渲染通道自动隐藏；无 python→兜底链路不可用提示） |
| 引擎回退 | auto=pptd 主引擎；硬失败→python-pptx 兜底**醒目标注**；显式指定引擎绝不静默降级 |
| 文件兼容 | UTF-8/UTF-16（WPS）XML 自动识别；store/deflate zip；媒体缺失→占位图（导入/导出双侧） |
| 坏输入 | 缺 deck.yaml / YAML 语法错误（附笔误指引）/ 元素级样式键 / 声明 id 防呆 / 空 pages / 0 元素页 / 2000 字长文——preflight A1-A6 全绿：**报错不崩溃，且报错带指引** |
| 幂等 | 路由（双源单装配 + refcount + 表判据）、autoDeclare、重复导出、重复 splice |

**已知边界（诚实声明，均有替代路径）**：字体观感假设（估算档；加粗 CJK 已×1.06 补偿）；EMF 媒体；跨平台（COM/Edge 探测面向 Windows）；pptxgenjs 未实现（D6 决策）；动画/阴影/超链接/母版继承不导入。**跨用户风险**：新用户首次遇到的"隐形契约"（样式键层级）已由 ppt_check 报错 + 手册 + skill 覆盖。

### 1.2 泛用性（功能/场景覆盖）—— 评级：良好（主线全覆盖，纵深有边界）

- 四类任务（from-scratch/augment/edit/summarize）语义路由 + quick/normal/audit 三档。
- 保真三通道（参考双轨 / 手术 patch / 替换 splice+slice）——"像 / 贴 / 保"全覆盖。
- 输入：.pptx 导入（参考层 + 全量色板 + safeArea 探测）；图表（bar/line/pie 矢量拼绘）；custGeom/渐变/alpha/prst。
- 覆盖盲区（文档化，不阻塞）：summarize 无"特殊化形态"（通用能力，C8 未实现）；多源内容合并/PDF 字典导入无；图表类型有限；line 仅 2 点。
- **E2E 佐证**：自建高难度夹具 12 页（声明制/安全区/渐变/alpha/custGeom/嵌套卡/表格/图表/跨页数字/来源标注）门禁 0 错误。

### 1.3 可维护性 —— 评级：优秀（本轮再加固）

- 免 tsc（src→lib）、无外部运行时依赖（yaml 唯一例外）、docs/ 五文件 + 本次 docs/06、git semver 约定。
- 测试四层：smoke 139（全链路）→ preflight 11（坏输入/边界/幂等/性能/媒体 splice）→ **e2e-1.0 12（自包含端到端：real browser measure + real Office COM render + 自产 seed 回导）** → regression-real 2（真实 WPS 资产）。
- **自包含化（本轮）**：历史外部资产已清理 → 夹具生成器 examples/fx + fixtures.mjs，`npm run test:e2e` 一条命令复现全部真机验证。
- 文档链同步约定（docs/05）；README 更新为手册（含开发维护 §10）。

### 1.4 可用性 —— 评级：良好 → 优秀（1.0.0 手册 + skill 后）

- 用户侧：四类任务自动路由；`ppt_schema` 自述；`ppt_new` 兜底样例；`ppt_preview` 同源链接对话内看稿；audit 档自动化（真渲染 + 回读断言）。
- 易踩坑点（本轮修复/覆盖）：样式键层级（报错+指引）；YAML flow 嵌引号；声明 id 防呆；隐藏契约不再静默。
- **1.0.0 新增**：README 使用手册（10 章，含 FAQ/边界/维护）+ **内置 skill `ppt-studio-manual`**（提问式学习：不用读完文档）。
- 已知摩擦（诚实）：Office COM 窗口闪现；20 个工具面名字多（工作流提示词引导降低迷路率）；估算保守产生"宁多不放过"的 warning（意图：防漏）。

### 1.5 严谨性 —— 评级：良好（本轮抓出 3 处并修复）

**本轮发现并修复（测试即审查）**：

| # | 发现 | 性质 | 修复 |
|---|---|---|---|
| G1 | `expectedOverlaps` 声明 id 无存在性防呆（对照 expectedOutOfSafeArea/contrastExempt 都有）——声明指向幽灵元素 = "以为声明了还报错" | 防呆缺口 | validatePage 同款校验 + preflight A4 |
| G2 | 空 `pages: []` 静默产出 0 页 pptx（PowerPoint 打不开） | 静默坏产物 | validateDeck ≥1 页拦截 + preflight A2 |
| G3 | README 三处过期（"实测档下一阶段/pptx 截图未实现/改一页手工姿势"——均为已实现历史） | 文档失真 | 手册重写为 v1.0.0 状态 |
| G4 | router 工作流提示词未含 splice/slice（编辑既有页的正确姿势） | 提示词缺口 | 铁律 7 增补交付路径指引 |

**核对未发现捷径的证据**：度量链真实闭环（textMetricsOf.overflowY = textH−boxH；verify 与 export 同一阈值，实测档交叉 D3）；声明制无豁免洞（content-collision 硬底线、decoration 不豁免出界、audit 禁 autoDeclare）；zip 手术（splice/slice）自证（SHA256 逐条目）+ Office 打开真值；无静默引擎切换（auto 语义写死）；ERROR 级从未降级（docs/05 底线）。

**尚存的"掩盖可能"（诚实）**：浏览器实测档默认关闭（老行为优先——跨字体环境差异时"估算通过但实测出错"需显式 `measured=true` 暴露；已在手册/提示词明示）；EMF/跨实现未验证；百页 deck 的 measure 是分钟级（文档标注）；autoDeclare 的"意图自证"是提示词约束（模型自律）而非机器验证（D1 设计如此，audit 档已机器禁用）。

## 四、核心亮点（1.0.0 叙事）

1. **声明制（设计意图）胜过元素类型制**：唯一让"有意叠层"合法的方式；content-collision 硬底线 + 声明闭包 + autoDeclare。这是"避免元素区块冲突"的机器化答案。
2. **可验证的生产线（三轨）**：数字门禁（快）/ 视觉审阅（慢但必要）/ Office 真渲染（有条件终极真值）+ M2 浏览器实测=终审——"质量不是靠运气"。
3. **保真交付一个命令**：splice（替换进原稿，其余页 SHA256 逐字节自证）/ slice（单页+完整母版）/ patch（贴模板）——"编辑既有精美 PPT"从手工 zip 手术变成工具。
4. **自包含范例生态**：内置模板（4 版权自研 + 外部模板双轨）、ppt_new 样例、examples/fx 高难度夹具——新人可学、可验、可复现。
