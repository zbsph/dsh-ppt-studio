# 11 · 术语表

> 目的：跨文档/跨会话统一用词。**新增术语先加到这里再使用**（尤其图子系统开工后）。
> 用法：文档里第一次出现某术语时，可回指本表条目号。

| # | 术语 | 含义 |
|---|---|---|
| 1 | **PPTD** | 本插件自研的中间层（`deck.yaml` + `pages/*.yaml` + 主题），介于"模型写的结构"与"OOXML 产物"之间 |
| 2 | **DSL** | 上述中间层的写法规则（由 `src/pptd/schema.js` 校验） |
| 3 | **元素（element）** | DSL 里的最小绘制单元：`text / shape / line / image / table / chart` |
| 4 | **页面（page）** | 一页幻灯片；含 `elements`、可选 `groups`、声明字段与讲稿 |
| 5 | **引擎 A / pptd 引擎** | 我们手写 OOXML 的导出主引擎（`src/pptd/export-pptx.js`） |
| 6 | **引擎 B / 兜底引擎** | python-pptx 兜底（`src/pptxPy.js`），主引擎硬失败时自动降级并标注 |
| 7 | **IR（中间表示）** | 图子系统的**结构描述层**（阶段 B 引入）：声明"有什么节点/关系/层次"，几何由布局引擎算 |
| 8 | **结构关系** | 图子系统里的类型化关系：`contains`（包含）/ `attach`（附着）/ `badgeOf`（徽章归属）/ `groups`（组合） |
| 9 | **组合（group）** | 用户工作方式中的"把若干元素当一个整体"；既用于剪枝/审阅，也用于导出真 `grpSp`（阶段 A 第二步） |
| 10 | **块（block）** | 可复用的组合（局部坐标 + 参数）；复用默认 **copy 语义**，不做隐式联动 |
| 11 | **声明（declaration）** | 设计期显式写下的意图：`expectedOverlaps`（有意重叠）/ `expectedOutOfSafeArea`（有意出安全区）/ `role` 覆盖（附 `roleReason`）/ 结构关系 |
| 12 | **豁免（exempt）** | 因**有效声明或结构关系**而不报冲突的对；**推导出的豁免不落盘**（每次现算） |
| 13 | **剪枝 ≠ 豁免** | 包围盒只能用来**排除候选**；剩下的必须落到元素级真实判断，否则是假阴性 |
| 14 | **几何反验证** | 对每条声明按几何实测核对（"声称包含"就实测真包含）；不成立 ⇒ 声明作废并按冲突报 |
| 15 | **门禁（gate）** | `ppt_verify` 的结论；ERROR 必须清零才能交付 |
| 16 | **冲突分级** | `content-collision`（内容互压，**永不可声明**）｜warning 级"设计预期外重叠"（可声明）｜超页面（**永不可声明**）｜超安全区（声明制） |
| 17 | **role** | 层叠角色：`background / content / decoration`；`decoration` 完全豁免重叠报告 |
| 18 | **autoDeclare** | 把警告级未声明重叠批量写入 `expectedOverlaps` 的一键操作 |
| 19 | **parity** | 导出后自证：期望 vs 产物（表/图/线/媒体/文本内容/图表部件/组/关系…），全部进 `parity.ok` |
| 20 | **内容级回读** | 从产物 OOXML 反推"该写的字/该画的图形在不在"，而不是读中间层 |
| 21 | **参考层** | `ppt_import` 保留的原始 pptx + 真渲染预览 + 色板，供"先看后做" |
| 22 | **样式档案** | 从 `$theme` 或参考稿提取的样式令牌（配色/圆角/线宽/字号阶梯/间距基数），图的风格来源 |
| 23 | **手术（surgery）** | 三类保真交付：`ppt_patch`（XML 级换文字）/ `ppt_splice`（只换一页，其余页逐字节不动）/ `ppt_slice`（单页独立版） |
| 24 | **loss-audit** | 导入时的"重建有损"审计：动画/阴影/超链接/切换/SmartArt/不可嵌入媒体/主题渐变 |
| 25 | **crosscheck** | 内容审阅材料包（跨页正文/表格/图表数据 + 素材清单 + 审阅协议），供模型判定四分类 |
| 26 | **P1 铁律** | 真渲染抽检铁律：含 table/chart/image/custGeom 的页必须真渲染 + 读图审阅 |
| 27 | **自证** | 由产物/真渲染反推结论的机器化证明（parity、内容级回读、官方 `check_office.py`、`git bundle verify` 式校验） |
| 28 | **隔离（isolation）** | 能力面只在「PPT 工作室」预设作用域注册；`scope: preset` 默认，`scope: profile` 为旧全局行为 |
| 29 | **装配档（tier）** | `profile`（插件随 profile 挂载）｜`preset`（随预设作用域挂载）；`assembly.tier` 可查 |
| 30 | **快测 / 全量 / 发版档** | `test:fast`（改动即跑）｜`npm test`（批次边界）｜`test:release`（发版，并行全档） |
| 31 | **硬门槛** | 阶段 A 起生效的四条量化门：确定性（两次导出逐字节一致）｜性能基线｜判据严格性与图进 parity｜常驻 token 增幅 ≤5% |
| 32 | **回归门** | 无图页产物逐字节不变、提示词只增行、既有断言全绿、隔离矩阵不变；任一破 ⇒ 回滚该阶段 |
| 33 | **图族（family）** | 一类图的结构模式：流程图/泳道/层级树/分层架构/时间轴/闭环/对比/矩阵/步骤环/漏斗/时序/状态机 |
| 34 | **maturity** | 图族的完成度标记：`stable`｜`beta`；未完成族必须**优雅降级**（退回简单布局或手写路径） |
| 35 | **北极星场景** | "给一份已有复杂图的 ppt，再加一页同风格复杂图"：import（参考+样式）→ IR → 布局 → splice |
| 36 | **审阅锚点** | 判断可信度的外部依据：可机械反查 → 门禁｜可证据核验 → 抽样复核｜纯审美 → 用户 |
| 37 | **缝合页** | IR 生成的块与手写元素混排、但未共享同一套约定 ⇒ "每件都不差、合起来不像一套" |
