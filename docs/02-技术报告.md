## 2. 模块明细

### 2.1 schema.js — 结构与归一化的权威
- 校验（所有错误一次性收集，PptError.messages 数组）：
  - deck：version/1、title、size（[w,h] 或对象）、theme.colors（hex 或 `$ref`）、theme.textStyles、`theme.safeArea`、`theme.minFontSize`。
  - page：elements（elementId 唯一、elementType ∈ text|shape|line|image|table|chart、bounds、role、各类型专属字段）、`expectedOverlaps`、`overlapMode`、`background`（hex/`$ref`/{solid}/{image}）、`safeArea`。
  - **line 的 bounds 可省略**（v0.3，D1）：校验放行，normalizePage 用 points AABB 推导。
- `resolveDeck(dir)`：读取 → 校验 → 返回 `{dir, deck, size(默认960×540), theme, colors, textStyles, minFontSize(默认12), safeAreaOf(page), resolveColor, styleOf, pages:[{file,ref,page,name,index}]}`。**读时快照**——页面 yaml 被外部改写后必须重新 resolveDeck（autoDeclare 流程已如此做，见 2.6）。
- `styleOf`：`style: "$name"` 引用 theme.textStyles + 页面内联字段覆盖（合并顺序：ref → own）。

### 2.2 layout.js — 三端共享度量（渲染/校验/导出）
- `charWidth`：CJK 1em / 空格 0.4em / 数字 0.6em / Latin 0.6em（bold 0.63）/ 全角标点 1em / 其他 0.65em（v0.3 偏宽保守档）。
- `wrapLines`：CJK 字符级 token + Latin/数字词级 + **标点禁则**（行首不落 `，。、！？；：）》」…`；行尾不落 `（《【「`）。
- `measureText` / `textMetricsOf`：输出 textW/textH/lines/**lineWidths**/overflowX/overflowY。**overflowY = round(高 − 容器高)，>1px 即溢出**（统一阈值 FIT_TOL=1，见 export）。
- `normalizePage`：页面元素 → 统一快照对象（id/type/bounds/role + 类型专属字段 + text metrics）。**三端（render/verify/export）共用** → 度量一致是"verify 通过 ⇒ 导出不缩字"的根基。

### 2.3 render-html.js — 预览 + layout.json
- 每页 → `preview/<NN>_<slug>.html`（单页，含内联页面背景）+ `preview/deck.html`（整览，共享 style + 各页内联背景；修复过"拼合丢样式"缺陷）。
- `layout.json` = **数字审阅的唯一数据源**：`{size, theme{colors,textStyles,grid,safeArea,minFontSize}, pages:[{index,file,name,background,safeArea,expectedOverlaps,overlapMode,elements:[snap]}]}`。
- snap 记录每元素 id/kind/bounds/role + 专属字段（text 含 style+metrics+text；shape 含 fill/rotation；line 含 points…
  **chart 从 2026-09-14 起含 `colors`**——verify 的"图表显式配色 vs theme.colors"建议必须看得到它，否则 layout.json 里只有 chartType、那条建议永不触发）。
- `debug=true`：文本描边 + **安全区参考框**（`.sa-guide` 蓝色虚线，v0.3）。

### 2.4 verify.js — 断言引擎与美学层
`analyzePage(page, size)` 产出 findings（severity: error/warning/confirmed/suggestion）：

| 断言 | 级别 | 说明 |
|---|---|---|
| out-of-page（页面边界） | ERROR | 超页面边界（放映不可见）——**永远不可声明**（出血设计见 docs/01 C11 待议）|
| out-of-page（安全区） | ERROR / confirmed | 超 safeArea 但页面内 → **声明制**：命中 `expectedOutOfSafeArea` → confirmed（✓ 预期出界），未命中 → ERROR（提示加入声明）|
| text-overflow | ERROR | wrap 看垂直（overflowY>1）/ wrap=false 看水平 |
| content-collision | ERROR | 内容面×内容面（text/table/chart），**不可声明豁免** |
| unexpected-overlap | ERROR | 警告级重叠未命中 expectedOverlaps（声明制） |
| expected-overlap | confirmed | 命中声明 → ✓ 不出现在错误/警告 |
| overlap（warning） | warning | line×任意（引线/箭头）与 内容×承载（shape/image 作底板）|
| near-align / hotspot / density | warning | 对齐启发式/密集区/密度 |
| aesthetic-* | suggestion | 8+3 条：重心/外边距/列数/间距节奏/网格/字号层级/主题颜色/文本密度 + **对比度**（WCAG，D6）+ **孤字**（末行 <1.5×fontSize，D7）+ **背景图无 safeArea 提示**（D5）|

**主题颜色一致性（第 7 条）的边界（2026-09-14 补）**：文本色 / 形状 fill / 线色都必须 ∈ `theme.colors` 或中性灰（strict 档为 ERROR，见 `themeConformance`）；
**图表配色刻意只做建议级**——`chart.colors` **显式**写了主题外颜色 → 一条 `[·] aesthetic-theme`（消息里点明"含图表显式配色"）；
**不写 `colors`（用内置调色板）不提示**，因为那是既有行为，提示只会给所有带图的老工程加噪声。
刻意**不**把图表配色纳入门禁：门禁化（改 `fillColorsOf`/`themeConformance`）会给既有工程与模板凭空新增 ERROR，
且 `theme-conformance` 不可声明 —— 那是"让老用户变差"。要改必须先设计"图表调色板如何纳入主题"（docs/04 待议）。

> 声明维度（v0.3.2 统一为"空间断言=设计意图声明制"）：重叠 = `expectedOverlaps`（可一键 autoDeclare）；安全区出界 = `expectedOutOfSafeArea`（**必须手工**，id 防呆）；页面出界 = 绝对（C11 待议）。

角色推断 `roleOf`：显式 role 覆盖；默认 text/table/chart=content、shape/image=background、line=line；`decoration` 完全豁免 overlap 报告。
`collectDeclarable(page, size)`：收集"警告级未声明重叠对"（供 autoDeclare；不含 content-collision、不含已声明、不含 decoration）。

### 2.5 layout.json 语义（三端契约）
- 渲染器写、verify 消费、**可选**与导出 .pptx XML 做产物快照交叉验证（tools.js `snapshotPptxShapes`：读 out.pptx zip，数 spTree 顶层形状——仅一致性提示，不算门禁）。
- 警告：**pptx 产物快照不是布局断言**（导出几何 = 中间层几何，因导出器与校验用同一 normalizePage；真正的"产物档"增强待 R2）。

### 2.6 autodeclare.js — 一键声明（D2）
`applyAutoDeclare(ctx, layout)`：逐页 collectDeclarable → `YAML.parseDocument` **只 setIn expectedOverlaps**（保留页面其余注释，规避 C3-safe_dump 全量重排问题）→ 写回 → 返回 `[{page, added, file}]`。
**调用方必须重新 resolveDeck 再渲染**（resolveDeck 是读时快照）——tools.js 已如此；smoke 也如此断言。
**yaml@2 读值教训（v0.14.6 反馈 A）**：`doc.get()` 返回 AST 节点（YAMLSeq 无 .map；`node.toJS()` 裸调用抛 "A document argument is required"）——读既有声明一律 **`doc.toJS()`**（Document 级，纯 JS 值），写仍走 `doc.setIn`；`templates.js` 同款（expectedOutOfSafeArea）一致处理。

### 2.7 export-pptx.js — 主引擎（pptd）
- 手写最小 OOXML：content-types / rels / presentation / slideMaster / slideLayout / theme / slides；1px=1pt，EMU=pt×12700。
- 元素映射：text→`p:sp`（txBody，auto-fit）、shape→`p:sp`（rect/roundRect/ellipse/triangle + rotation）、line→`p:cxnSp`（straightConnector1 + tailEnd 三角箭头）、image→`p:pic`（blipFill 嵌入）、table→`graphicFrame a:tbl`、chart→**矢量拼绘**（bar=矩形、line=连接线+圆点、pie=饼形 `prst=pie` 带 adj1/adj2）。
- **连线编码三件事（2026-09-14 两轮修复，都在这一层）**：
  ① **方向**：`straightConnector1` 在 OOXML 里只画包围盒左上→右下，真实走向必须靠 `flipH`/`flipV`（p2 在 p1 左侧→flipH；上方→flipV）；漏写会镜像斜率、并让 × 的两笔重合成一条。
  ② **箭头**：`<a:tailEnd>` 必须写在 `<a:ln>` **内部**（写在 `spPr` 里 PowerPoint 静默忽略，预览却有——预览是 render-html 自己画 marker）。
  ③ **包围盒精确等于线段跨度**：不能 `max(1,…)` 兜底，否则水平线 `cy=1pt` 会被画成"12pt×1pt 的对角线"＝假斜线（`cy=0`/`cx=0` 合法，Office 自己也这么写）；只有零长线给 1×1 兜底。
  **自证**：`connectorEndsFromXml()` 从写出的 XML 反解端点并与源 `points` 逐条比对（<0.01pt），并断言 arrow=true 时 `tailEnd` 在 `a:ln` 内；
  结果进 `report.parity.lines{Exp,Out,Wrong}`，`parity.ok` 同时要求表/图/线三项归零。这是"预览层对、成品层错"这类跨层不一致的机器防线。
- 页面背景：`p:bg` 原生（solidFill / blipFill + 媒体嵌入 + rels，v0.3 修复）。
- `out`：**绝对路径原样使用 / 相对路径相对 deck 目录**（E1）。
- **auto-fit 与下限**（E2 修复；2026-09-06 下限语义修订）：只缩当 `overflowY > 1`（与 verify 同阈值）→ verify 通过 ⇒ 不缩字；**下限 = 用户指令**：`theme.minFontSize` 显式 → `min(原字号, 用户下限)`（绝不升字）；未设置 → 无强制（60% 原字号防荒谬保底，最低 6pt）；到下限仍溢出 → `floorHit: true` 进 report（工具输出 ✗ 警告，绝不静默）。
- **自动回退链**（C1）：tools.js `resolveEngine` 决定——auto=pptd+allowFallback；pptd 硬失败 → python-pptx 兜底（报告醒目标注降级）；显式指定不回退。
- **引擎档位不静默（2026-09-18 修，两处）**：① `resolveEngine` 对**未知取值**返回 `unknown` 标记而非静默当成 auto
  （历史形状：命令面接受 `/ppt engine pptxgenjs` 并回执"已记录（待接入）"，导出侧却把它当 pptd 跑，报告一字不提——违反明文红线"不静默切换引擎"）；
  ② `/ppt engine X` 设的是**会话/项目档位**，而 `ppt_export` 旧实现只看工具参数 ⇒ 该档位**设了没用**（报告里的 `引擎` 行还显示用户选的那个）。
  现在 `qualityOfDiag` 把档位一并带出，`ppt_export` 在工具参数缺省时**采纳**它；未知取值会在导出报告里明说"已按 auto 处理，没有静默按你的选择跑"。
  `pptxgenjs` 未实现（v1.0 前按计划不动）⇒ 命令面**明确拒绝**，不再收下并装作成功。
- **出界分级分码（2026-09-18 修）**：`out-of-page`（超**页面边界**：放映不可见、**不可声明**、必须改布局）与
  `out-of-safe-area`（超**安全区**但仍在页面内：**可声明**，补 `expectedOutOfSafeArea` 即可）**拆成两个错误码**。
  此前两者共用 `out-of-page`，于是"分级"这个设计概念在 code 维度上丢失——消费方（`templates.js` 的清理统计、
  任何按 code 的诊断）与模型都无法区分该做什么。两者 severity 都是 error ⇒ 属**诊断精度**修复，对既有工程零影响。
  `audit-manual-facts.mjs` 的"decoration 不豁免出界"运行时事实随之改判为 `out-of-safe-area`。
- **兜底引擎的生成物必须过真消费者（2026-09-18 修，四处失效一次全中）**：`pptxPy.js` 把中间层映射成 **python 源码**再 subprocess 执行。
  该路径此前在 `scripts/` 里**零调用**——从未被任何测试执行过，而它是"pptd 硬失败时"的最后保险。实测四种失效：
  ① **SyntaxError**：填充/描边被写成单行条件表达式 `x = a if c else (y = b, …)`——赋值是语句不是表达式，**连编译都过不去**；
  ② **NameError `undefined`/`null`**：fill / line 缺省时把 JS 的 `undefined` / `null` 插值进了 Python 源码；
  ③ **AttributeError**：`{color, alpha}` 被 `JSON.stringify` 成 dict 直接喂给 `rgb()`；
  ④ **NameError `true`**：`JSON.stringify` 产出的是 **JSON**（`true`/`false`/`null`）而非 Python 字面量——样式字典 `{"wrap":true}` 直接进脚本，
      而**文本是最高频路径**，等于兜底引擎对几乎任何 deck 都不可用。
  另有第五处：`add_text` 把样式设在 `paragraph.font` 上再 `p.text = …`（`p.text` 会新建 run，样式全丢）——导出"看着有字、样式全无"。
  修法：填充/描边改为生成**语句**；新增 `pyLit()`（JS 值 → Python 字面量）替换数据类插值；样式改设到 **run** 上；
  `OUT` 改为变量（旧实现导出时只替换 save 行，`print` 仍读 `sys.argv[1]` ⇒ **文件已写出却报执行失败**）。
  诚实边界：alpha / 渐变在兜底引擎里按**纯色近似**，脚本内留注释（原生引擎 pptd 保留原样）。
  防线：smoke §43 两条——`py_compile` 必须过 + 必须真跑出 .pptx 且 **python-pptx 能读回**（1 页 ≥ 6 形状）。
  校验含义：这条正是"跳过与通过印同一个颜色"的典型——python 是可选依赖，缺了打一行"跳过"算绿，于是没人发现它连编译都过不去。
- **表格字号三层同源（2026-09-18 修，自相矛盾）**：表格 cell 原本在导出侧硬编码 `sz="1100"`（11pt）、预览侧硬编码 `font-size:12px`——
  同一份内容两层不一致，且都绕开 `theme.minFontSize`。后果：audit 档的回读断言扫**全 slide XML** 取全局最小 sz 与下限比，
  只要工程里有表且用户下限 ≥ 12，audit **永远 ✗**，而 DSL 里没有任何手段能改表格字号（把用户逼到无法满足的门禁）。
  修法：字号由 `layout.js` 的 **`tableCellFontPt(ctx) = max(11, theme.minFontSize)`** 算一次，`normalizePage` 挂到元素的 `fontPt` 上，
  预览（cell px）与成品（`sz`）都读它 ⇒ 三层不可能再各写一个数。默认值仍是 11pt，**未声明下限的既有工程观感零变化**。
  防线：smoke §44 两条（三层同源 + 成品最小 sz ≥ 用户下限）。
- **表格内容溢出进门禁（2026-09-18 修，内容门禁的盲区）**：`layout.js` 的表格分支此前只产出 cols/rows 的**长度**，
  而 `verify.js` 的溢出判定只认 `kind === 'text'` ⇒ **表格内文字溢出既无门禁也无警告**。
  而表格是 `role: content` 的内容元素——"内容溢出/互压"正是硬底线要管的，属"该严的地方没严"。
  修法：`normalizePage` 按**列宽换行**（复用 `wrapLines`，同一保守度量）算出每行需求高度 →
  快照带 `metrics.overflowY`；`verify.js` 的溢出分支并入 `table`，用**独立错误码 `table-overflow`**
  （处置不同就分码：表格的杠杆是行列尺寸与文案，不是文本框）。
  **影响面先测后改**：仓库全部夹具 2 张表、**0 张**会被判溢出（余量 -228 / -52.8）⇒ 对既有工程零影响；
  e2e 的"fx-pro verify 门禁 0 错误"仍绿。
  注意：错误码提取器是**文本启发式**，要求 `code: '字面量'` 写法——写成三元会让码从守卫视野里消失（本轮踩到，已改独立分支）。
- **audit 回读断言**（D2）：audit 档导出后自动读产物 OOXML，校验页数/尺寸（EMU 精确）/最小字号 ≥ minFontSize，逐项 ✓/✗ 追加进报告。
- **讲稿 → 备注页（2026-09-14 新增）**：页面 `notes:`（非空字符串）→ `ppt/notesSlides/notesSlide<N>.xml` + `ppt/notesSlides/_rels/notesSlide<N>.xml.rels`（rId1→notesMaster、rId2→回指本页幻灯）+ `ppt/notesMasters/notesMaster1.xml`(+rels→theme)，
  并补幻灯 rels（notesSlide 关系）、`[Content_Types]` 两条 Override；文本按 `\n` 分段成多个 `a:p`（实体转义走 `xm()`）。
  编号只为"有讲稿的页"分配（1..N），**没有 notes 的页不产生任何备注部件**（这类工程产物与旧实现逐字节一致）。
  **两个必须照 PowerPoint 原生形状写、否则真 PowerPoint 打不开的点**（实测二分定位）：
  ① notesSlide 的占位符必须能在 notesMaster 里找到对应项（body 用 `idx="3"`、幻灯图 `sldImg idx="2"`）——notesMaster 因此不能是空 spTree；

- **性能（D5 基准）**：100 页 render 70-406ms；measure **220-320s**（顺序 3.2s/页；优化链：并发 4 + 每进程独立 user-data-dir（共享 profile Singleton 锁串行化是首轮大坑）→ 2.2s/页；budget 减小无益（虚拟时间快进非线性））。20 页常用 ≈ 45s。
- **交叉语义**（verify.js `measuredCrossCheck`）：实测溢出且估算未报 = **error（估算漏报——M2 核心捕获）**；实测复现 = warning；估算报但实测通过 = relief warning（字体差异人工确认）；行数差异 = suggestion；旋转元素排除几何漂移。`ppt_verify measured=true` 默认关闭（老行为不变）。
- **两档页号契约（2026-09-18 修，假绿灯事故）**：`layout.json` 与 `measured.json` 每页都写 **1 基 `pageNo`**，交叉核查**按 pageNo 配对**；`index` 退回"各自文件的内部数组下标"（两侧都 0 基）。
  事故：此前按 `index` 配对，而 layout 的 index 是 0 基（render-html 取 schema 的 pages.length）、measured 的 index 是 **1 基**（`i+1`）⇒ **永不配对、恒返空结果**，界面上显示"✓ 全部一致或实测通过"。
  更隐蔽的是 offset 恰为 1：若两侧元素 id 跨页复用，会拿第 N 页的实测去比第 N+1 页的估算。
  **契约破坏现在响亮报错** `measured-unpaired`（缺 pageNo / 找不到对应页），不再静默 `continue`——静默返空与"真的没问题"在输出上不可区分，这正是它藏了整轮 1.0.0 的原因。
  防线：smoke §27 四条**真产物**断言（页号契约 / 第 2 页注入必被捕获 / 第 1 页注入不得串页 / 缺 pageNo 必须报错），全部由 `ppt_render` + `ppt_measure` 真跑产物驱动。
- **诚实边界**：测量 = Chromium 排版真值（系统字库），仍非 PowerPoint 引擎；与 ppt_shot 同渲染链（字体/尺寸差异同源）。

### 2.17 crosscheck.js — M3 数据连贯（跨页对账 + 证据核查表）
- 跨页数字对账：页面 text/table 文本数字+百分比提取 → 同数字跨页入组（页号+上下文，cap 30）——"同一指标多页值不一致"的发现机制（建议级，语义判断人工）。
- 证据核查表：页面 `source` 标注 → grounded / unmapped（**按页判、不看这页有没有数据**；工具本身是建议级，不进门禁）。

### 2.18 装配与安装（2026-09-14：新增 profile bundle 路径）
- **两条互斥的挂载路径**（细节见 docs/01 决策 11、README §0.7）：
  | 路径 | 载体 | 层级 | 由谁写 |
  |---|---|---|---|
  | profile bundle 行 | 包的 `cordis.patch.yml`（`dsh.bundle.patch` 指向） | **profile 级**（所有会话） | `dsh plugin --profile <p> add <包>`（launcher 自动入 `dsh.profile.bundles`） |
  | agent preset 插件行 | `~/.dsh/.agent-presets/ppt/agent.cordis.yml` | **会话级**（仅该预设） | `scripts/install.mjs` |
- **`dsh plugin` 的真实语义**（harness 源码 + 真机实验双证）：它是**薄 pnpm 转发器**——在 profile 目录跑 `pnpm <args...>`，随后
  `reconcilePlugins()` **按已安装状态**核对 `dsh.profile.bundles`：依赖解析出的包**声明了 `dsh.bundle.patch` → 自动入栈**；
  没有声明 → 打一行 "declares no dsh.bundle … not a profile layer" 警告（装了不挂载——本包在 2026-09-14 之前正是这个状态）。
  对 path/git/tarball/alias 规格按**真实包名**入栈，所以"从 GitHub Release 的 tgz URL 安装"不需要 npm 账号。
- **装配防重**（`index.js`）：同进程第二次 apply 直接计数并告警、**不重复注册**（tools/commands/技能/监听器都是"按名注册"的服务，重复注册会撞名）。
  用 `globalThis.__pptCoreReg` refcount（跨模块实例共享；模块级变量在 junction/真实路径双加载下不可靠）。
  注意 `ctx.effect` 语义（§2.12）：清理必须写成**返回函数** `() => () => { count-- }`。
- **互斥由安装器机械保证**（2026-09-15）：`install.mjs` 检测 profile 的 `package.json` 依赖 / `dsh.profile.bundles` 是否已含本包
  → 是（bundle 模式）则 **跳过 junction**（该路径归 pnpm 管，`--force` 也不能动）、**不动包内 node_modules**、
  并在写预设时**删掉插件行标记块**（`# >>> dsh-ppt-studio plugin row` … `# <<< …`）。
  为什么必须做进安装器：预设是"以包为准总是刷新"的托管文件，**手工删行会被下一次同步装回来** → 又变成双挂载。smoke §41 用两个临时 prefix 真跑安装器验证两种模式。
- **发布流程与新装法对齐**（`release-sync.mjs` 第 ⑤b 步）：bundle 模式下**挂载源是 pnpm 的快照**，不再是"部署副本被 junction 指向"，
  所以发布后要按**同一 GitHub 资产 URL** 重新 `add`，并用**逐文件 sha256 比对**（部署副本 vs 挂载副本）自证同源；不一致则 remove+add 重取。
  `.sync-state.json` 记 `mode: local|release`、`mount: bundle|bundle-local|preset-junction`、`mountMatch`、`assetUrl`、`localTgz`、`lastReleaseAt`。
- **两种同步模式**（2026-09-18）：**日常迭代** `release-sync --local` **不发 GitHub**，用**本地 tgz 的 `file:` 规格**装进 profile
  （构件落在 `D:\plugins\_artifacts\`，**稳定目录**——它就是 profile 的依赖规格，放 tmpdir 会在系统清理后让下次 `pnpm install` 莫名失败；旧构件自动清理只留当前那个），
  判据从"== GitHub"改为"**挂载副本 == 刚构建的字节**"；**发版**（不带 `--local`）仍做三向 sha256 校验，把本机与 GitHub 拉回同源。
  为什么 `--local` 走 `file:` 而不切回 junction/preset 装法：junction 会**新增一条挂载路径**（"我改的是哪份代码"有两种答案，答错不报错），
  `file:` 仍只有一条路径（profile bundle 行）。**⓪ 落后检查**：`--local` 先 `git fetch` 比对 `HEAD` 与 `origin/<branch>`，落后即失败
  （`--allow-behind` 绕过）——"本地永不落后于 GitHub"**不会自动成立**，且破了以后没有任何症状。
- **资产名带构建时间 + 构建戳**（2026-09-15，同日两次修正）：`<版本>-<YYYYMMDD-HHmm>-<tgz sha256 前 8 位>.tgz`。
  ① **戳**：实测同一 URL 被 `--clobber` 覆盖后 `dsh plugin add <同一 URL>` **不会重取**（pnpm 侧按 URL 复用；独立 GET 证明 URL 已是新字节），
  固定名会让"重跑同一条命令升级"静默拿到旧版本；换名 ⇒ URL 必变 ⇒ 必然重取（反向也已实测：`test:bundle` 的升级自证证明新规格真换成新字节且 bundles/dump-config 不丢）。
  ② **时间**：Release 页面**有意保留历次构建**（老 URL 留给已装用户重装——删掉会让他们的 `pnpm install` 失败），
  于是页面上并排多条"长得像"的资产，而 sha 段看不出新旧 ⇒ 加 `<YYYYMMDD-HHmm>`，"取时间最新那条"即可判定当前版本。
  **取法要按上传时间，不能按文件名排序**（实测踩到）：老的无时间戳资产名 `…-1.0.0-ad78a36d.tgz` 在字典序里排在
  `…-1.0.0-20260916-0226-….tgz` **之后**，`sort | tail -1` 会取到旧版本 ⇒ 正确命令是
  `gh release view v1.0.0 --json assets --jq '.assets | sort_by(.createdAt) | last | .name'`（README §0.2 同步）。
  探针：`npm run probe:asset -- <URL> [marker] [期望sha256]`（直接 GET + 解包；**判决以 sha256 为准**，marker 只作线索）。
- **包名是单一事实源**：`package.json.name` 必须与 `cordis.patch.yml` 的 insert 行、预设插件行三处一致——smoke §40 有断言钉住。
- **重解析点安全**（配套探针 `npm run probe:reparse`）：`release-sync` 会 `rmSync(D:\plugins\package, {recursive:true})`，而该目录里有
  `node_modules/yaml` junction → 探针实测 **Node 的 rmSync 不跟随 junction**（金丝雀目录存活），该删法安全；
  但**PowerShell 的 `Remove-Item -Recurse` 会跟随**（2026-09-14 事故）——删含 junction 的目录一律先 `cmd rmdir` 链接。
- **自证**：`npm run test:bundle`（`scripts/verify-bundle-install.mjs`）——隔离 `DSH_HOME` 起临时 profile → 真 `dsh plugin add <tgz>` →
  断言"无 no-dsh.bundle 警告 + 已进 bundles 层栈 + 已物化 + dump-config 出现 ppt-studio 行"，**不碰用户 profiles**。
- `ppt_shot overview=true`：deck.html 整览截图（N 页纵排，>30 截前 30）——跨页节奏视觉审阅。

## 3. 核心机制解读（改这些地方 = 改项目哲学，须更新 01 文件）

1. **设计意图声明制**：重叠合法性来自"设计时声明、审阅时对照"，不是元素类型。底裤 = content-collision 永不可声明。
2. **双轨审阅**：数字门禁（快、可全自动）+ 视觉审阅（截图、防估算漏报）。估算档被真实任务证明会骗过（第 6 页溢出截图才发现），视觉审阅因此是"必要"而非"可选"。
3. **声明制成本控制**：四个缓冲——`autoDeclare` 一键批量（重叠）、`declaredClosure` 嵌套闭包（相邻层声明隔层自动）、`overlapMode: lenient`（草稿）、`role: decoration`（装饰豁免重叠）+ `contrastExempt`（对比度误报豁免）。
4. **度量一致性**：三端共用 normalizePage + wrapLines；verify 的 TOL(1px) 与 export 的 FIT_TOL(1) 相同 ⇒ 门禁通过 = 导出不缩字 = 承诺兑现（14pt/12pt 下限）。
5. **引擎质量优先**：auto=pptd；python-pptx 降级为表格，仅显式切换 —— 与设计文档"自动回退链"存在 C1 冲突（待确认，见 01 文档）。
